# 监控一个远程站点 {#monitor-a-remote-site}

一个 DumbMonit,多个网络。安装在远程站点的**中继代理**会代表
服务器执行分配给它的设备探测,并通过它已经用来推送自身指标的
那个出站连接来报告结果。远程站点无需打开任何端口,不需要 VPN,
也不需要第二个实例来查看。

```
 总部                                     远程站点(NAT、防火墙)
 ┌──────────────────┐   HTTPS,出站       ┌──────────────────────────────┐
 │ DumbMonit 服务器  │◀────────────────────│ 中继代理                      │
 │  调度器          │  要运行的探测  ──▶  │  运行 SNMP / Proxmox / HTTP…  │──▶ 交换机、NAS、
 │  告警、UI        │◀── 样本、结果       │  同时推送自己的指标           │    虚拟化平台……
 └──────────────────┘                     └──────────────────────────────┘
```

## 1. 通过 HTTPS 发布服务器 {#1-publish-the-server-over-https}

中继代理会从服务器获取其任务:服务器必须能被远程站点访问,
通常是反向代理之后的 `https://monitor.example.org`。在这条
连接上传输的内容有两种:

- **注册令牌**(`dmon_…`),在每个请求的 `Authorization` 请求头
  中——与任何代理一样;
- 中继代理探测的设备的**设备凭据**(SNMP 社区名、Proxmox API
  令牌……),经过解密,包含在每个探测任务中。

通过纯 HTTP 跨越互联网传输时,两者在传输途中都是可被读取的:
在向你自己网络之外中继任何内容之前,请把服务器放在 HTTPS 之后。
在局域网或 VPN 上,HTTP 是可以接受的,此时令牌是唯一在传输中的
密钥,直到你把设备分配给该中继代理。凭据在任何一侧都不会被写入
磁盘:一个探测任务只存在于服务器的内存中,直到中继代理报告它;
代理在两次探测之间不会保留任何内容。

反向代理必须像转发 `/api/ingest` 一样转发 `/api/agent/relay`,
允许最多 16 MB 的请求体(一台繁忙的虚拟化平台会报告数千个
样本),并把空闲连接保持至少 60 秒:服务器在等待任务时(长轮询)
会把一次中继请求保持最多 25 秒。

## 2. 创建一个注册令牌 {#2-create-an-enrollment-token}

**设置 → 代理 → 新令牌**,或添加一个类型为*代理*的设备。复制
`dmon_…` 的值:它只会显示一次。

## 3. 在远程站点启动中继代理 {#3-start-the-relay-at-the-remote-site}

远程站点上任何带有 Docker 的机器,使用仓库中的
`docker-compose.agent.yml`:

```sh
DUMBMONIT_AGENT_URL=https://monitor.example.org \
DUMBMONIT_AGENT_TOKEN=dmon_… \
DUMBMONIT_AGENT_HOSTNAME=relay-lyon \
DUMBMONIT_AGENT_RELAY=true \
DUMBMONIT_AGENT_SITE="Lyon office" \
docker compose -f docker-compose.agent.yml up -d
```

或者使用一行命令安装程序安装的普通代理,在
`/etc/dumbmonit/agent.yaml` 中再加两个键:

```yaml
relay: true
site: Lyon office
```

该机器会在几秒钟内出现在 DumbMonit 中,作为一台普通的代理设备,
其页面会显示*中继 · 站点 Lyon office · 中继 0 台设备*。代理的
日志会在其首批数据被接受后显示 `relay mode enabled: waiting for
probes from the server`。

!!! note "中继代理需要能访问的内容"
    中继代理是从它自己的网络探测设备的:它需要与服务器如果身处
    那里时所需的同样的访问权限——SNMP 用 UDP 161,Proxmox 用
    8006,DSM 用 5001,等等。对于**ping**监控,容器需要
    `cap_add: [NET_RAW]`(参见 compose 文件)。对于 VLAN 或
    链路本地网络上的设备,或 `localhost` 目标,请使用
    `network_mode: host`。

## 4. 把设备分配给中继代理 {#4-assign-devices-to-the-relay}

照常添加远程设备——SNMP 交换机、Proxmox 节点、HTTP 检查——
使用**从远程站点看到的**地址(`192.168.10.1`、
`https://pve.lan:8006`)。在设备表单中,于*更多选项*下,把
**访问方式**设为该中继代理,而不是*直接*。已有的设备也可以用
同样的方式切换;切回*直接*会让服务器重新轮询它们。

从那之后:

- 服务器会在每个间隔为该设备排入一次探测;中继代理会在几毫秒内
  取走它(它在服务器上等待任务),运行采集器并报告结果;
- 设备页面上的**立即探测**和配置档案检测也会通过中继代理进行;
- 该设备的*上次探测*和错误遵循中继代理的结果。当中继代理未能
  及时取走一次探测时,该设备会显示*超时:中继代理……未能取走
  该探测*——请检查该代理是否以 `relay: true` 运行;
- 该代理的页面会显示*为 N 台设备中继*,`GET /api/relays` 会列出
  各个中继代理及其站点和计数。

## 中继代理宕机时的告警 {#alerting-when-the-relay-is-down}

一个陷入静默的中继代理会连带影响它负责的设备:它们的探测会
停止,它们本会同时全部变为*不可达*。该中继代理会被视为它探测的
每个设备的**父设备**(在你可能设置的父设备之外):当该中继代理
本身*不可达*时,其设备的告警会显示为 `suppressed`,
`suppressed_by` 指向该中继代理,且只会发出一条通知——针对该
中继代理本身。你明确设置的父设备仍保留其角色,并在两者都宕机时
优先生效。

## 限制 {#limits}

- 每台设备只能有一个中继代理。由中继代理探测的设备不会同时也被
  服务器探测。
- 代理设备本身不能被中继:它们推送自己的指标。
- 该中继代理最多同时运行 8 次探测;一次探测受服务器探测超时
  (`DUMBMONIT_PROBE_TIMEOUT`)的限制,在代理上上限为 120 秒。
- 一个中继代理需要内置采集器:早于这项功能的代理会忽略
  `relay: true`,服务器会把它们的探测报告为超时。请用当前的
  二进制文件或镜像重新安装。
