# Запуск демо-инстанса

Публичная демонстрация на **[demo.dumbmonit.app](https://demo.dumbmonit.app)**
— это обычный образ DumbMonit, запущенный с `DUMBMONIT_DEMO=1`. Вы можете
запустить то же самое сами — чтобы показать DumbMonit команде перед настоящей
установкой, или чтобы разместить витрину на собственном сайте.

!!! warning "Никогда на настоящем томе данных"
    Демо-режим **пересоздаёт базу данных при каждом запуске**. Дайте ему
    собственный том или вообще без тома: направленный на `/data` настоящего
    инстанса, он заменит ваши мониторы, правила и историю условным парком
    мониторов.

## Что делает демо-режим

- **Вход `demo` / `demo`.** Страница входа сообщает об этом и заполняет поля
  в один клик. Учётная запись видит каждый экран, который видит администратор.
- **Только чтение.** Каждое изменение — мониторы, правила, заглушения,
  подтверждения, каналы, токены, пользователи, настройки, резервные копии и
  восстановления, сканирования обнаружения, регистрация агентов, инструменты
  записи конечной точки ассистента — отклоняется сервером с кодом `403` и
  `{"error": "This is a read-only demo…", "demo": true}`. Вход и выход — это
  единственные разрешённые записи. Интерфейс показывает сообщение там, где
  произошёл клик.
- **Два вымышленных клиента.** При запуске база данных создаётся заново и
  заполняется домашней лабораторией в `*.home.arpa` — Proxmox VE, NAS Synology
  с iSCSI LUN, Proxmox Backup Server, TrueNAS, OPNsense, UniFi, Kopia, сервер
  Redfish с неисправным компонентом, коммутатор SNMP, проверки HTTP, TLS, DNS и
  ping, Linux-агент с Docker — а в режиме MSP ещё и небольшим архитектурным
  бюро в Женеве: контроллер домена Windows со своим агентом, Veeam Backup &
  Replication, сеть Omada, Microsoft 365 и Entra ID, опрашиваемые через
  агент-ретранслятор в офисе. На запросы мониторов отвечают имитации устройств
  внутри сервера, привязанные к `127.0.0.1` и воспроизводящие записанные
  ответы API: работают настоящие сборщики и панели. После перезапуска парк
  тот же.
- **Тридцать дней истории и весь остальной продукт.** При запуске
  синтетические метрики записываются в VictoriaMetrics ограниченными блоками
  (последняя неделя с шагом пять минут): графики, *Последние 7 дней*,
  доступность за 30 дней, прогнозы, матрица резервных копий и история
  оповещений заполнены, а несколько оповещений активны. Начальные данные
  заполняют и то, что обычно настраивают вручную: команды и папки, учётные
  записи и графики дежурств с политиками эскалации, тишины, инструкции, две
  панели, плановые отчёты, каналы уведомлений (никогда не используются),
  площадки на карте мира, известные уязвимости, четыре страницы статуса (по
  одной на ночную сцену) с текущим инцидентом и сканирование сети с новым
  устройством. Всё вычисляется из фиксированного зерна: из сети ничего не
  загружается, даже источники уязвимостей. Поиск по журналам выключен: в
  демо нет хранилища журналов.
- **Ничего не уходит за пределы сервера.** Уведомления никогда не отправляются,
  и ни одна проверка не идёт на адрес, введённый посетителем.
- **Вводный тур** открывается после первого входа; баннер открывает его снова.

Ограничение частоты входа работает как обычно. Разместите демо за обычным
обратным прокси с HTTPS и задайте `DUMBMONIT_COOKIE_SECURE=1` и
`DUMBMONIT_TRUSTED_PROXIES`, как для любого публичного инстанса.

## Запуск

```bash
docker run -d --name dumbmonit-demo -p 8080:8080 \
  -e DUMBMONIT_DEMO=1 \
  ghcr.io/laupernoe/dumbmonit:latest
```

Или с Compose, без тома, чтобы каждый перезапуск начинался с чистого листа:

```yaml
services:
  dumbmonit-demo:
    image: ghcr.io/laupernoe/dumbmonit:latest
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      DUMBMONIT_DEMO: "1"
```

Регулярно скачивайте новый образ (или дайте это делать инструменту типа
Watchtower): тогда демо всегда показывает последний релиз с теми же данными.
