# Обновление DumbMonit

DumbMonit сообщает, когда выходит новый релиз, и проводит вас через обновление.
Он никогда ничего не устанавливает самостоятельно.

## Обнаружение новой версии

Не чаще раза в день сервер запрашивает публичный API релизов GitHub
(`api.github.com/repos/laupernoe/dumbmonit/releases`) на последний релиз и
сравнивает его с версией, которую вы используете. Предварительные релизы, такие
как `0.1.0-alpha.7`, сравниваются корректно: `alpha.10` новее, чем `alpha.9`, а
`0.1.0` новее, чем любой `0.1.0-alpha.N`. Черновики игнорируются, и инстансу на
стабильной версии предварительный релиз никогда не предлагается.

Когда есть более новая версия, в правом нижнем углу каждой страницы и в
**Settings → About** появляется надпись **Update available: vX**, где
**How to update** открывает шаги ниже, а **See what's new** снова открывает
окно *What's new*. **Check now** проверяет сразу же (не чаще раза в минуту).

!!! note "Что отправляется"
    Один анонимный запрос `GET` с user agent `DumbMonit/<версия>`. Ничего о
    вашем инстансе, устройствах или сети не отправляется, а адрес зафиксирован
    в коде.

### Отключение проверки

Для изолированных сетей отключите **Check for new versions** в
**Settings → About** (администраторы), либо задайте переменную окружения,
которая имеет приоритет над переключателем:

```yaml
environment:
  DUMBMONIT_UPDATE_CHECK: "off"
```

Та же информация доступна скриптам и токенам API через `GET /api/update`.

## Обновление

1. **Сделайте резервную копию.** Скачайте резервную копию в **Settings →
   Backup** и сохраните копию `/data/secret.key` (см.
   [Резервное копирование и восстановление](backup.md)). Без этого ключа
   сохранённые пароли и токены не расшифровать.
2. **Скачайте и перезапустите**, из каталога, где лежит ваш
   `docker-compose.yml`:

    ```bash
    docker compose pull && docker compose up -d
    ```

    Ваши данные хранятся в томе `/data` и сохраняются; миграции базы данных
    выполняются при запуске.
3. **Обновите страницу.** **Settings → About** покажет новую версию и
   *You are up to date*.

Чтобы закрепить конкретную версию, а не следовать за `:latest`, измените тег
образа в файле Compose (например `ghcr.io/laupernoe/dumbmonit:0.1.0-alpha.7`) и
выполните ту же команду.

Чтобы вернуться назад, восстановите резервную копию, сделанную на шаге 1, на
предыдущем образе.
