# 添加第一个监控项 {#add-your-first-device}

添加任何东西的方式都是一样的:从列表中选择一种类型,右侧的提示
会说明需要在监控项上准备什么,表单只会显示该类型真正需要的字段。

## 最初三步 {#the-three-first-steps}

在一个全新的实例上,概览页面不会显示一份空简报:它会显示一个
简短的引导——**添加你的第一个监控项**、**连接一种被告知的方式**、
**检查消息能否送达**。每一步只需一次点击,每一步完成后会自行
变绿。第三步只会在确实有一条消息真正从某个渠道发出之后才算完成,
因此创建了渠道却从未测试它并不算完成这一步。

该引导的状态保存在实例上,而不是浏览器中:跳过某一步,或跳过
整个引导,会在每个浏览器和每个用户中同样被跳过。三个步骤都完成
后,它会永久消失,并且在一个已经有监控项和渠道的实例上永远不会
出现——升级不会给一个已经建立好的家庭实验室塞一份教程。

## 添加一台 SNMP 设备 {#add-an-snmp-device}

SNMP 是最通用的类型:几乎所有网络硬件都支持它。交换机、路由器、
NAS、UPS 和打印机是最常见的对象。

1. 在监控项上启用 SNMP v2c,并记下只读社区名(许多监控项默认为
   `public`)。如果监控项按地址过滤,请允许 DumbMonit 服务器的
   地址。
2. 在 DumbMonit 中,打开**监控项**并点击**添加监控项**(或按
   ++ctrl+k++ 并输入"add")。
3. 选择**SNMP 设备**。选择器会折叠成一行,表单会显示 SNMP 相关
   的字段。
4. 输入一个**名称**、**地址**(IP 或主机名)和**社区名**。对于
   SNMP v3,把凭据切换为*SNMP v3*,并填写用户名以及认证和加密
   密码。
5. 点击**添加监控项**。

![添加一台 SNMP 设备:左侧是表单,右侧是设置提示](../assets/screenshots/add-device-light.png){ loading=lazy }

采集配置档案会在后台根据监控项的 `sysObjectID` 自动检测,因此表单
从不会因为一个不可达的监控项而等待。接口,以及在服务器和 NAS 上的
CPU、内存和存储,会在一分钟内出现。

!!! warning "社区名以明文传输"
    SNMP v1/v2c 的社区名在网络上不是加密传输的。在共享网络中,
    优先使用具备认证和加密的 SNMP v3。

## 扫描网络 {#scan-a-network}

与逐一输入监控项不同,也可以扫描一个地址段:

1. 在**添加监控项**上,打开**扫描我的网络**面板。
2. 以 CIDR 表示法输入一个网络,例如 `192.168.1.0/24`(每次扫描
   最多 4096 个地址),以及要在每个地址上尝试的社区名(默认
   `public`)。
3. 每个有应答的地址都会被列出,附带其 `sysName`、描述以及将被
   应用的配置档案。已在 DumbMonit 中存在的监控项会标注*已添加*,
   所有新监控项会自动勾选。
4. 取消勾选你不想要的监控项,然后点击**添加 *n* 个监控项**。它们会
   逐一创建,每一行都显示各自的结果,因此一次失败绝不会阻止
   其余监控项的创建。

## 添加一台 Proxmox VE 服务器 {#add-a-proxmox-ve-server}

同样的流程,只是凭据分为两个字段而不是一个:

1. 在 Proxmox 中,创建一个专用于监控的用户、一个只读角色和一个
   API 令牌——四条 `pveum` 命令就在表单旁边的提示中,每条都带有
   复制按钮,也可以在[Proxmox VE 页面](../devices/proxmox.md)中
   找到。绝不要重复使用你自己登录用的账户。
2. 在 DumbMonit 中,**添加监控项** → **Proxmox VE**。
3. 输入一个**名称**和任意一个节点的**地址**(默认端口 8006)。
4. 把令牌的**完整令牌 ID**(`dumbmonit@pve!monitor`)复制到
   **令牌 ID**中,把它的**值**(UUID)复制到**密钥**中。如果
   不小心把整段 `user@pve!name=secret` 字符串粘贴进了令牌 ID,
   表单会自动拆分它并提示你。
5. Proxmox 自带自签名证书:如果首次探测对此提出异议,请在
   *更多选项*下勾选**接受无法验证的证书**。
6. 点击**添加监控项**。

[Proxmox Backup Server](../devices/pbs.md)的操作方式相同,使用
`proxmox-backup-manager`;[Synology NAS](../devices/synology.md)
需要一个专用的 DSM 账户(用户名和密码);
[带代理的服务器](../devices/agent.md)完全不需要任何凭据,只需要
监控项保存后显示一次的注册令牌。

## 设置提示 {#the-setup-notice}

每种类型都带有自己的提示,由服务器编写,显示在表单旁边:需要在
监控项上执行的带编号步骤(创建只读用户、创建 API 令牌、允许该
地址……),附带产品中确切的菜单路径,每条命令或数值都有一个复制
按钮,随后是一个常见的坑和(如果有)指向厂商文档的链接。本文档
中各类型的专属页面与此逐字一致——服务器内的一项测试保证了它们
始终相同:[SNMP](../devices/snmp.md)、
[Proxmox VE](../devices/proxmox.md)、
[Proxmox Backup Server](../devices/pbs.md)、
[Synology DSM](../devices/synology.md)、
[代理](../devices/agent.md)、[服务](../devices/services.md)。

每份提示背后的原则:一个专用的只读账户,绝不是你自己登录用的
那个。一个泄露的监控密钥必须不能更改任何内容。

## 通用字段 {#common-fields}

无论什么类型,表单都包含:

| 字段 | 含义 |
|---|---|
| 名称 | 在列表和告警中如何显示该监控项。 |
| 地址 | 根据类型不同,为 IP、主机名、`host:port` 或 URL;占位符文字会显示预期的格式。 |
| 凭据 | 该类型接受的凭据种类,每种都有自己的字段:社区名、SNMP v3 用户和密码、Proxmox 令牌(令牌 ID + 密钥)、用户名和密码。密钥字段带有显示/隐藏的眼睛图标,粘贴的值会自动清除多余的空格、引号和换行符。存储时是加密的,API 从不返回它:编辑时,留空字段会保留已存储的值。 |
| 检查间隔 | DumbMonit 多久读取一次该监控项。默认 60 秒,最小 10 秒。 |
| 父监控项 | 如果父监控项宕机,该监控项的告警会被抑制而不是发送。参见[依赖抑制](../alerting/index.md#dependency-suppression)。 |
| 已启用 | 被暂停的监控项不会被检查,也不会触发告警。 |
| 标签 | 自由的键/值标签,会作为 `tag_<key>` 复制到每个序列上。特定类型的选项也在这里,位于**更多选项**下。 |

## 接下来会发生什么 {#what-happens-next}

- 该监控项会以机架面板的形式出现在**监控项**页面上:状态灯、名称、
  类型、地址、上次上报时间,以及一个迷你图。
- 测量数据会每 5 秒(`DUMBMONIT_FLUSH_INTERVAL_SECS`)写入
  VictoriaMetrics,因此第一次探测加上几秒钟后就会出现第一张
  图表。监控项页面上的**立即探测**会强制执行一次探测,并报告产生
  了多少样本和序列:这是主要的诊断工具。
- [内置告警规则](../alerting/rules.md)会立即生效:监控项不可达、
  CPU 饱和、磁盘即将用尽,等等。无需任何配置。
- 若要收到通知,请在**设置 → 通知与报告**中添加一个
  [通知渠道](../notifications.md)。内置规则会通知每一个已启用的
  渠道。

!!! tip "一分钟后仍没有数据?"
    打开监控项页面:配置错误(错误的社区名、被拒绝的证书、缺失的
    能力)会以红色显示在地址下方,并附带原因。参见
    [常见问题](../faq.md#no-data-after-adding-a-device)。
