# 设备页面 {#the-devices-page}

![机架:每台设备对应一个面板](../assets/screenshots/devices-light.png){ loading=lazy }

## 机架 {#the-rack}

每台设备都是机架上的一个 1U 面板:一个状态灯、名称、类型标签、
地址、上次上报时间,以及一个代表性指标的迷你图。子设备堆叠在
其父设备下方,当父设备不可达时会变暗。

| 状态 | 含义 |
|---|---|
| Reporting(上报中) | 最近一次探测成功,且处于最近三个周期之内。 |
| Unreachable(不可达) | 设备未应答(超时、连接被拒绝),或超过三个周期(至少 90 秒)没有探测。 |
| Misconfigured(配置错误) | 最近一次探测在我们这一侧失败:凭据错误、地址或选项无效、应答异常。以提示色显示错误信息;不会触发告警。 |
| Waiting(等待中) | 刚添加,尚未探测。 |
| Disabled(已禁用) | 已暂停:不会被检查,不会触发告警。 |

筛选器:一个搜索框、一个状态分段(全部、需要关注、上报中、
已禁用)和一个类型筛选器。**添加设备**是主操作按钮。

## 设备详情 {#a-device}

![设备页面:状态、操作、告警、类型专属面板、指标](../assets/screenshots/device-light.png){ loading=lazy }

设备页面显示其状态标牌、地址、类型、检测到的配置档案、标签、
上次探测时间,对于服务类设备还会显示证书状态。操作:

| 操作 | 效果 |
|---|---|
| 立即探测 | 立即执行一次探测,并报告产生了多少样本和多少序列。当设备没有数据时,这是首先要尝试的操作。 |
| 编辑 | 打开与添加时相同的表单,并预先填好内容。将凭据留空会保留已存储的值。 |
| 静默 1 小时 / 静默至… | 针对该设备的一次性维护窗口。 |
| 删除 | 内联显示"确定要永久删除?"五秒钟,然后删除该设备。其序列数据会保留在 VictoriaMetrics 中,直到保留期结束。 |

下方是**该设备上的告警**——每条活跃告警都提供*确认*、*暂缓*和
*忽略*操作,被忽略的规则会单独列出,并带有**停止忽略**按钮——
再往下是**指标**,可按时间范围(1 小时、6 小时、24 小时、7 天)
查看,每个指标名称一张图表,每个序列一条线。参见
[处理告警](alerts.md#getting-rid-of-an-alert)。

服务类设备(HTTP、TCP、DNS、ping、TLS)则会得到不同的仪表:
过去 24 小时或 7 天的**可用性**、**响应时间**、**检查次数**,以及
一条**历史记录**条形图(最早在左侧),显示该服务何时宕机。

## 容器策略 {#container-policies}

在带有代理且运行 Docker 的机器上,标题下方会有一条 **Docker** 状态条:
容器数量、正在运行的数量、可用更新的数量,以及设置了策略的容器数量。
**管理容器**会打开列表;**策略…**会打开一个表格,每个容器有两个开关,
并带有一行"应用到全部":

- **宕机时重启**——服务器会在容器停止运行后一分钟内将其重启
  (最多每十分钟一次);
- **在维护窗口内自动更新**——当镜像仓库中存在同一标签的更新镜像时,
  容器会在计划的维护窗口内(告警页面 → 已计划)被重新创建,
  如果健康检查失败则会回滚。

每个开关各自独立保存。详情和安全规则参见
[Docker 容器](../devices/agent.md#docker-containers)。

## 添加与编辑 {#adding-and-editing}

关于表单内容参见[添加第一台设备](../install/first-device.md),
关于各类型所需内容参见[设备类型](../devices/index.md)。编辑时,
如果设备已经使用了某个选项,表单会自动展开**更多选项**。

## 删除 {#deleting}

删除设备会将其从配置中移除,立即清除其告警——不会发送任何通知,
历史记录中会留下一行 `device removed or disabled`——并在几秒钟后
从内嵌的 VictoriaMetrics 中删除其时间序列(尽力而为:失败只会被
记录日志,随后这些序列会随着 12 个月的保留期自然过期)。暂停设备
同样会清除其告警;其序列数据则会保留。
