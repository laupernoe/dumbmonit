# 告警页面 {#alerts-page}

![告警页面:当前正在发生的事、维护、历史和规则](../assets/screenshots/alerts-light.png){ loading=lazy }

关于告警的一切都集中在这一页,分为四个标签。标签会体现在 URL 中
(`/alerts#rules`),因此某个视图可以直接被链接。**计划维护**
按钮在右上角,可从任意标签打开该窗口的表单。

| 标签 | 内容 |
|---|---|
| **当前** | 实时的问题列表,每个问题一行。参见[“当前”列表](#the-now-list)。该标签以及顶部栏中"告警"上的徽标,就是当前仍需要处理的数量。 |
| **维护** | 维护窗口,*当前生效*或*已计划*,一次性、每周或每月,各自标注下一次出现的时间(`#scheduled`)。参见[维护窗口](../alerting/maintenance.md)。 |
| **历史** | 最近 200 条转换记录,每条标注监控项、规则和发生的情况;已解决的记录可以被清除。 |
| **规则** | 每条规则及其严重级别、一个*内置*标记,以及如果有任何监控项忽略它,则显示*在 N 个监控项上被忽略*;可以启用、就地编辑、删除你自己创建的规则、创建一条阈值规则。参见[规则](../alerting/rules.md)。 |

通知渠道和通知策略位于**设置 → 通知与报告**(参见[通知](#notifications))。

概览简报和这个页面使用同一套真实状态模型,因此两者对"什么需要
处理"的判断始终一致。

## “当前”列表 {#the-now-list}

每个问题一行:状态图标、出了什么问题、哪个监控项、一行说明的原因、
多久之前,以及行内的**确认**和**打开**。各行按严重级别分组(警告、
提示、信息、正在积累、被父监控项抑制),也可以用**严重级别 | 监控项**
开关改为按监控项分组。分组可以折叠;*被抑制*、*已暂缓*和*已忽略*
(已确认)分组默认折叠。同一条规则在同一监控项的多个序列上触发,
只算一行("……另外还有 7 条")。

点击某一行可展开详情:所有受影响的序列、从何时开始、谁确认了它、
为什么被抑制,并提供**打开监控项**、**暂缓**和**此监控项永不提醒**。

同时选择多行是一种模式。**选择**按钮(操作员和管理员可用)会在每一行
显示复选框,并在底部显示一个浮动栏,包含**全选**、**确认**、**取消确认**、
**对此监控项忽略**和**完成**。按 Escape 退出该模式。

## 处理告警 {#getting-rid-of-an-alert}

一条触发中的告警不是非黑即白的——"修复它"或"永远忍受这份噪音"。
有四种操作,对应四种不同的场景,管理员和操作员均可使用(查看者
能看到状态,但不能更改它):

- **确认**("我在处理")适用于你正在积极处理的某一条告警:
  "我知道了,4 小时内别再提醒我"。菜单提供 1 小时、4 小时、24
  小时或*直到解决*,外加一条给你之后查看该卡片的人的可选备注。
  该告警仍会继续触发和评估;只有它的提醒和升级会暂停——包括
  升级到第二个渠道。它解决时你仍会被告知,确认状态也会在那一刻
  清除——之后再次出现的告警会重新发出通知。该卡片会从主列表
  移到更安静的*已确认*分组中,显示为"由某人确认,直到某个
  时间",并提供**取消确认**按钮。
- **暂缓**适用于"现在不处理,稍后再看",而不声称你正在做任何
  处理:1 小时、8 小时、1 天或*直到解决*。与确认不同,它的实现
  方式是打开一个只针对该条告警精确标签的维护窗口——同一监控项上
  的相邻规则仍会继续发声。该卡片会移到一个显示剩余时间的安静的
  *已暂缓*分组中,并提供**取消暂缓**按钮。提醒会以与确认相同的
  方式暂停。
- **忽略**("不要再就此提醒我")适用于某条规则在这个监控项上永远
  不合理的情况:它会单独为该监控项禁用这条规则(一种按监控项的覆盖
  设置——参见[按监控项的覆盖设置](../alerting/rules.md#per-device-overrides)),
  该告警会立即永久消失,而不只是被安静处理。这是可逆的:在监控项
  页面上点击**停止忽略**,或在"告警 → 规则"中该规则本身那一行,
  那里会显示*在 N 个监控项上被忽略*。
- **清除**针对的是历史记录,而不是实时告警:一旦某条转换记录已
  解决,*清除*(或*清除所有已解决*)会把它从默认的历史视图中
  移除。该行数据仍保留在数据库中——不会被删除——*显示已清除*
  可以把它找回来。

公开状态页面会忽略确认和暂缓状态:一条被确认或暂缓的告警,对
外部世界来说仍然是一条告警。而被忽略的规则则从一开始就不会
产生任何告警。

## 通知 {#notifications}

渠道和策略位于**设置 → 通知与报告**(`/settings/notifications`),
其后是[报告](reports.md)。两个面板:

**通知渠道。** 渠道列表,每个都标注其类型、*已启用*或*已禁用*、上次
发送的时间,以及上次的错误(如果有)。**添加渠道**会根据服务器
对所选类型的描述打开一个表单:设置项(可见)和密钥(只写)。
**发送测试**会发送一条测试消息,并就地显示结果。每个渠道的
**投递选项**包含其最低严重级别、是否接收解决通知、每条告警的最小
间隔,以及它的**静默时段**(每周,按你的时区:只有警告级别的
告警会通过,其余会等待摘要)。

**仅限部分告警。** 同样的投递选项中还包含该渠道的**路由过滤器**:
它想要哪些告警,按监控项标签(`site=cellar`)、按监控项类型
(`proxmox`),或按规则。同一字段上的多个条件按*或*关系处理,
不同字段之间按*且*关系处理,*除外*这一行始终优先生效。在编辑器
下方,一个预览会列出该过滤器当前选中了你的哪些监控项,还有一句话
会把整个规则复述给你——例如"该渠道接收标签为 site=cellar 的
监控项发出的提示级别及以上的告警,除了标签为 role=lab 的监控项"。
没有设置过滤器的渠道会继续接收所有内容,这也是每个已有渠道的
默认行为。

编辑一个渠道并把密钥留空会保留已存储的值。渠道类型及其字段记录
在[通知渠道](../notifications.md)中。

内置告警规则会通知每一个已启用的渠道;一条规则也可以在其编辑器
中被限定为仅使用特定渠道。

**通知策略。** 用于保持通知数量精简的全局开关:批处理窗口、
每个渠道每小时的上限、**更多选项**下的抖动检测、"在 DumbMonit
中打开"链接所使用的公开 URL,以及**升级**这一行——*如果在一段
延迟内没有人确认*,*则同时通知*另一个渠道,仅一次。该延迟从第一
条消息实际发出的那一刻开始计算,确认该告警(或它被解决)都会
停止这次升级。参见[通知策略](../alerting/notifications.md)。

原来的链接(`/alerts#notifications`、`/alerts#notifications-policy`、
`/settings#notifications`)会转发到这里。

## 操作员与查看者 {#operators-and-viewers}

**操作员**处理告警,但不触及配置:他们可以确认、暂缓、为单个
监控项忽略某条规则、创建或删除维护窗口,以及清除已解决的历史记录。
规则、渠道和通知策略对他们保持只读,标注为*操作员——配置仅限
管理员*。忽略是操作员唯一能做的按监控项覆盖设置;阈值仍由管理员
决定,操作员的*忽略*或*停止忽略*会保留管理员为该监控项设置的任何
阈值。

查看者能看到每一个标签,但没有任何控制权:在管理员会看到按钮的
地方,页面会显示*查看者——只读*。
