# Оценка безопасности

Каждое поддерживаемое устройство получает **оценку безопасности** от 0 до 100 и оценку
от **A** до **F**, в духе PingCastle или Microsoft Secure Score:
список проверок, взятых из собственного руководства лучших практик поставщика, каждая из которых
проходит, не проходит или не оценивается.

Оценка появляется как карта **Безопасность** на странице устройства, и на
странице **Безопасность**, которая перечисляет каждое оцениваемое устройство, худшее сначала.

## Как вычисляется оценка

DumbMonit никогда не спрашивает устройство ничего лишнего для вычисления оценки. Проверки
читают последние значения, которые сборщики уже записали (возвращаясь
на 6 часов), поэтому оценка не стоит устройству ничего и работает в автономном режиме от
последнего зонда.

Каждая проверка имеет:

| Поле | Значение |
|---|---|
| Категория | раскрытие, патчинг, аутентификация, шифрование, резервное копирование или конфигурация |
| Серьезность | критическая, высокая, средняя или низкая — ее вес в оценке: 10, 6, 3, 1 |
| Результат | **pass**, **fail**, или **unknown**, когда данные не собираются |
| Доказательство | что было наблюдено: `pve1: 3 обновления безопасности`, `Истекает через 9 дней`… |
| Исправление | что делать в терминах поставщика |
| Руководство поставщика | страница поставщика (или стандарт), на которой основана проверка |

**Оценка** = 100 × (вес пройденных проверок) ÷ (вес прохождения + отказа
проверки). **Неизвестные проверки показаны, но никогда не считаются**, ни за, ни
против: оценка не должна упасть, потому что маркер мониторинга не хватает привилегии,
и не должна подняться, потому что ничего не известно. Устройство, чьи проверки
все неизвестны, *не оценивается*.

| Оценка | Оценка | Слово |
|---|---|---|
| A | 90–100 | Сильно |
| B | 75–89 | Хорошо |
| C | 60–74 | Справедливо |
| D | 40–59 | Слабо |
| F | 0–39 | Плохо |

**Отказавшая критическая проверка ограничивает оценку на C**, какова бы ни была оценка:
брандмауэр, который больше не фильтрует, или активно используемое встроенное ПО, оставленное
без патчей, не компенсируется десятью незначительными хорошими параметрами. Карта говорит так
когда это происходит.

## История и оповещения

Сервер пересчитывает каждую оценку каждые 15 минут и хранит её как
`dumbmonit_security_score{target="<id>"}` (и количество неудачных проверок как
`dumbmonit_security_checks_failed`), чтобы вы могли построить график и предупредить о ней, как
любой другой метрики. Два встроенных правила используют его:

- **Оценка безопасности упала** — оценка упала на 10 пунктов или более в сравнении
  с его лучшим значением последних 24 часов: что-то новое не работает.
- **Оценка безопасности низкая** — оценка ниже 40 (оценка F). Отредактируйте правило для
  переместить пороговое значение на собственное.

См. [Правила оповещений](../alerting/rules.md#security-score).

## Проверки по видам

### Proxmox VE

| Проверка | Серьезность | Данные |
|---|---|---|
| Установлены обновления безопасности | высокая | ожидающих обновлений безопасности на узел (нужна `Sys.Modify` на маркере, иначе неизвестно) |
| Пакеты Proxmox VE актуальны | средняя | обновляемые пакеты Proxmox на узел |
| Выполнен установленный ядро | средняя | установлено новее ядро, чем запущено |
| Нет стандартного репозитория в использовании | средняя | включены стандартные репозитории |
| Репозитории пакетов правильно настроены | средняя | ошибки и предупреждения, которые Proxmox VE поднимает на репозитории (например репозиторий enterprise без подписки) |
| Подписка на репозиторий предприятия | низкая | статус подписки на узел |
| Сертификат веб-интерфейса действителен на 14+ дня | средняя | истечение сертификата узла |
| Каждый гость находится в задании резервного копирования | высокая | гости не выбраны никаким заданием резервного копирования |
| Задания резервного копирования успешны | высокая | последний результат каждого задания резервного копирования |

Источники: [Обновления системного ПО](https://pve.proxmox.com/wiki/System_Software_Updates),
[Репозитории пакетов](https://pve.proxmox.com/wiki/Package_Repositories),
[Управление сертификатами](https://pve.proxmox.com/wiki/Certificate_Management),
[Резервное копирование и восстановление](https://pve.proxmox.com/wiki/Backup_and_Restore).

### Мониторы TLS и HTTPS

Для мониторов `tls`, `http`, `smtp`, `mqtt` и `websocket`, которые ведут переговоры TLS.
Простой монитор на основе текста не имеет карты безопасности.

| Проверка | Серьезность | Данные |
|---|---|---|
| Сертификат действителен на 14+ дня | высокая | дни до истечения |
| Цепь сертификатов доверяется | высокая | проверка цепи |
| Согласован TLS 1.3 | низкая | согласованная версия протокола |

Источники: [Mozilla Server Side TLS](https://wiki.mozilla.org/Security/Server_Side_TLS),
[NIST SP 800-52 Rev. 2](https://csrc.nist.gov/pubs/sp/800/52/r2/final),
[Руководство интеграции Let's Encrypt](https://letsencrypt.org/docs/integration-guide/).

### Серверы времени NTP

| Проверка | Серьезность | Данные |
|---|---|---|
| Сервер сообщает синхронизированные часы | средняя | слой и индикатор скачка |
| Смещение часов в пределах 100 мс | низкая | измеренное смещение |

Слой 16 (или 0, "kiss-o'-death") и индикатор скачка "несинхронизированный" оба не проходят
первую проверку независимо от смещения: сервер, который
никогда не синхронизировался, не имеет ничего достоверного для предложения. Пороговое значение 100 мс
фиксировано здесь и не следует опции "Допустимое
смещение" на устройство, так же как проверка сертификата всегда предупреждает в четырнадцать
дней независимо от собственных параметров монитора.

Источник: [RFC 5905](https://www.rfc-editor.org/rfc/rfc5905).

### Nginx и Apache httpd

| Проверка | Серьезность | Данные |
|---|---|---|
| Заголовок Server не раскрывает версию | низкая | заголовок ответа `Server`, захваченный рядом со страницей статуса |

Заголовок, который все еще называет продукт ("nginx", "Apache") без номера версии
проходит: это то, что `server_tokens off` и `ServerTokens Prod`
производят, и отсутствующий заголовок тоже проходит. Заголовок, такой как "nginx/1.25.3" или
"Apache/2.4.58 (Unix)", не проходит: это сообщает сканеру точно, какие CVE попробовать.

Источники: [Справка основного модуля Nginx](https://nginx.org/en/docs/http/ngx_http_core_module.html#server_tokens),
[Справка основного модуля Apache](https://httpd.apache.org/docs/2.4/mod/core.html#servertokens).

### Active Directory

Устройство Active Directory оценивается из находок в стиле PingCastle его сборщика:
Kerberoastable учетные записи, учетные записи без предварительной аутентификации Kerberos, неограниченная делегирование, возраст пароля `krbtgt`,
размер привилегированной группы, охват LAPS, политика паролей, устаревшие учетные записи. Каждый
вывод - это проверка, которая проходит, когда она касается нулевых объектов; серьезность
сборщик сообщает, это тот, который используется. Выводы еще не сообщены
перечисляются как неизвестные.

Источники: [Правила проверки здоровья PingCastle](https://www.pingcastle.com/PingCastleFiles/ad_hc_rules_list.html),
[Microsoft — неограниченная делегирование Kerberos](https://learn.microsoft.com/en-us/defender-for-identity/security-assessment-unconstrained-kerberos),
[Windows LAPS](https://learn.microsoft.com/en-us/windows-server/identity/laps/laps-overview),
[Сброс пароля krbtgt](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/forest-recovery-guide/ad-forest-recovery-resetting-the-krbtgt-password).

Источник: [API параметров приложения GitLab](https://docs.gitlab.com/ee/api/settings.html).

## Ограничения

Оценка отражает только то, что может видеть DumbMonit. Это подсказка для поиска, а не
аудит, и оценка A не означает, что устройство защищено.

Лучшие практики, которые **не** проверены, потому что сборщики не
читают данные сегодня:

| Тип | Не проверено (требуется новые данные) |
|---|---|
| Proxmox VE | брандмауэр центра обработки данных/узла включен; двухфакторная аутентификация на `root@pam` и других учетных записях администратора |
| Proxmox Backup Server | шифрование резервных копий на стороне клиента (нужно чтение манифестов резервного копирования) |
| Synology DSM | двухшаговая проверка для администраторов; учетная запись `admin` по умолчанию отключена; автоматическое блокирование; брандмауэр DSM; перенаправление HTTP-в-HTTPS; раскрытие QuickConnect; доступно ли новое обновление DSM |
| OPNsense / pfSense | веб-интерфейс или SSH доступны из WAN; учетные данные по умолчанию; обновления системы pfSense (не REST API) |
| UniFi | SSH устройства с учетными данными по умолчанию; параметры сайта |
| Мониторы TLS | TLS 1.0/1.1 или слабые наборы шифра все еще предлагаются — зонд только ведет переговоры TLS 1.2 и 1.3, поэтому сервер, ограниченный старыми версиями, показывает как неудачный зонд вместо |
| Хосты агента | статус брандмауэра хоста; конфигурация SSH; статус Windows Defender |
| Docker | контейнеры, работающие привилегированные, как корень, или с смонтированным сокетом Docker |

Другие ограничения:

- Проверка только так свежа, как ее данные: некоторые сборщики повторно читают обновления или
  подписки каждые несколько часов.
- Веса являются выбором продукта, одинаковыми для каждой установки.
- Типы без любой проверки не имеют карты безопасности и не появляются на
  странице безопасности.
