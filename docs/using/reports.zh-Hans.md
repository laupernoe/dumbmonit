# 邮件报告 {#email-reports}

报告是一封简短的邮件,告诉你的团队基础设施在过去一天、一周或
一个月里的运行情况,而不需要任何人打开 DumbMonit。默认是每周
发送一次;每日和每月只需一次点击即可切换。报告复用一个**邮件
(SMTP)通知渠道**,所以请先设置好一个(参见
[通知渠道](../notifications.md))。

打开**设置 > 报告**来设置它们。这里的一切都只有管理员可见——
包括读取——因为该页面会列出收件人的地址。

## 报告包含的内容 {#what-a-report-contains}

| 部分 | 内容 |
| --- | --- |
| **标题** | 该周期内的总体可用性、事件数量,以及与上一周期相比的变化。 |
| **按组别的可用性** | 每个组一行,再按设备细分(最多显示可用性最低的 40 个),计算方式与[状态页面](status-pages.md)相同:探测按成功率计算,主机和设备按上报频率计算。没有历史数据的设备会显示为“无数据”,而不是显示为 100%。 |
| **事件** | 每个事件何时开始、持续了多久(或仍在进行中)、发生在哪台设备上。最多 25 条。信息性告警不包含在内。 |
| **最不稳定的设备** | 可用性最低或事件最多的五台设备。 |
| **对比** | 与之前同样长度周期相比的可用性和事件数量。 |

邮件是带有内联样式的纯 HTML 表格,不包含任何远程图片,因此无论
在哪里打开都显示一致,打开时也不会去获取任何内容。同时会附带
发送一个文本版本。每一个设备名称和消息都会被转义。

## 设置项 {#settings}

| 设置项 | 作用 |
| --- | --- |
| **名称** | 仅在列表中显示。 |
| **启用** | 关闭后会保留设置但不发送任何内容。 |
| **频率** | 每日、每周(默认)或每月。 |
| **日期** | 每周报告的星期几,或每月报告的日期(1 到 28)。 |
| **时间**与**时区** | 报告何时发出,使用 IANA 时区,例如 `Europe/Paris`。会遵循夏令时。 |
| **收件人** | 最多 20 个地址,自由填写:不必是 DumbMonit 用户。每位收件人会收到属于自己的邮件,因此谁也看不到别人的地址。 |
| **邮件渠道** | 由哪个 SMTP 渠道发送。默认是第一个已启用的渠道。只会使用该渠道的邮件服务器;其自身的收件人设置会被忽略。 |

周期是一个滚动窗口,在报告发送时结束:过去 24 小时、7 天或 30 天。
上一周期是紧邻其前、长度相同的窗口。

点击部分标题旁边的 **i** 图标可查看该部分内容的提示。

## 发送预览 {#send-a-preview}

**发送预览**会立即把当前报告发给已保存的收件人,主题中带有
`[Preview]`。这不会改变任何计划安排:下一次报告仍会按时发出。
每份报告每 30 秒最多可发送一次预览。请先保存你的更改,因为
预览使用的是已保存的收件人。

## 投递保证 {#delivery-guarantees}

- **最多发送一次。** 在构建邮件之前,该时间槛位就已在数据库中被
  占用,因此重启绝不会导致同一份报告被发送两次。当发送失败时,
  错误会被记录在该报告上并显示在列表中,该时间槛位不会被重试;
  下一次仍会照常发出。
- **不会补发。** 如果 DumbMonit 在预定时间处于宕机状态,只有当
  恢复的时间在该时间槛位之后 3 小时以内时,才会补发报告。超过
  这个时间,就会等待下一个时间槛位。你新建或重新启用的报告永远
  不会补发已经过去的时间槛位。
- 最多可以存在 10 份报告。
- 在演示模式下不会发送任何内容。

报告包含在[备份](../install/backup.md)之中:恢复时会按名称匹配
邮件渠道,恢复后的报告会重新开始(不会带入上次发送的日期)。
