# Forgejo / Gitea

Forgejo и Gitea используют один и тот же REST API, поэтому DumbMonit читает
оба одним сборщиком: отвечает ли инстанс, его проверку здоровья, сколько у
него репозиториев, учётных записей и организаций, продолжают ли его плановые
задачи (проверки репозиториев, очистки, проверка обновлений) выполняться в
свой интервал, и в сети ли его раннеры Actions.

Должны пройти два вызова: `/api/v1/version`, публичный, и `/api/v1/user` —
доказательство того, что **токен доступа** действителен. Всё остальное —
проверка здоровья, счётчики репозиториев/учётных записей/организаций,
плановые задачи и раннеры Actions — читается из конечных точек, которые
Forgejo и Gitea резервируют для учётных записей администратора сайта, и
пропускается без провала проверки, когда токен принадлежит обычной учётной
записи.

Отказ, за которым здесь стоит следить: **плановая задача, которая перестала
выполняться**. Forgejo и Gitea продолжают отдавать страницы и операции git,
пока их внутренний планировщик застрял; никто не замечает, пока проверка
обновлений или проверка целостности репозитория не выполнялась неделями.

## Что отслеживается

Все метрики с префиксом `dumbmonit_forgejo_`.

| Метрика | Что | Метки |
|---|---|---|
| `version_info` | значение 1 | `version` |
| `token_is_admin` | 1, когда учётная запись токена — администратор сайта | |
| `healthz_ok` | 1, если проверка здоровья не сообщает `fail` | |
| `healthz_check` | 1 на каждый отказавший компонент (база данных, кэш) | `check` |
| `repos` | репозитории, видимые учётной записи токена | |
| `users`, `orgs` | учётные записи и организации на инстансе | |
| `cron_tasks` | плановые задачи, определённые на инстансе | |
| `cron_task_overdue` | 1 на каждую задачу, чей следующий запуск уже должен был состояться, иначе 0 | `task` |
| `runners_total`, `runners_online`, `runners_offline` | раннеры Actions, известные инстансу | |
| `runner_offline` | значение 1 на каждый раннер не в сети (не более 32) | `runner` |
| `scrape_errors` | вызовы, доступные только администратору, завершившиеся ошибкой при последней проверке (0, если вызовы с обычным токеном даже не предпринимались) | |

Применяемые [встроенные правила](../alerting/rules.md#self-hosted-forges):
«Все раннеры Forgejo/Gitea не в сети», «Плановая задача Forgejo/Gitea
просрочена», плюс «Устройство недоступно». Оценка безопасности проверяет
плановые задачи: см. [Обновления от вендора и другие проверки](../using/security-score.md).

## Что не отслеживается

У Forgejo и Gitea нет роли администратора только для чтения: каждый вызов,
зарезервированный для «admin», требует учётную запись с полными правами, а не
делегата с ограниченной областью. Их API также не имеет аналога настроек
GitLab о регистрации или двухфакторной аутентификации, ни собственного флага
«доступно обновление» — сравнивайте версию выше с
[заметками о релизах](https://forgejo.org/releases/) проекта вручную.

## Страница устройства

Панель над графиками читает то, что сохранила проверка; открытие страницы
никогда не обращается к Forgejo или Gitea. Сначала она сообщает, что не так
(проверка здоровья не проходит, все раннеры не в сети, просроченная плановая
задача), затем — версию, затем — счётчики репозиториев, учётных записей и
организаций.

## Создание токена доступа на учётной записи администратора сайта

1. Создайте токен доступа на учётной записи администратора сайта: avatar → Settings → Applications → Generate new token. Назовите его так и отметьте области read:admin, read:repository и read:user.

    ```
    dumbmonit
    ```

2. read:admin открывает счётчики администрирования, плановые задачи и раннеры Actions; без него читаются только версия и собственная учётная запись токена, а остальное пропускается без провала проверки. У Forgejo и Gitea также нет роли администратора только для чтения.

3. В DumbMonit введите адрес, например «forgejo.lan» (порт 3000) или «https://git.example.com» за обратным прокси, и вставьте токен.

!!! warning
    Токен доступа на учётной записи администратора сайта может читать и менять всё, что может сама учётная запись, независимо от отмеченных областей: Forgejo и Gitea ограничивают лишь то, какие маршруты API открывает область, а не то, сколько может сама учётная запись администратора. Выделите для этого отдельную учётную запись бота, а не используйте свою собственную.

Проверка токена вручную, с хоста DumbMonit:

```
curl --header 'Authorization: token YOUR-TOKEN' 'https://git.example.com/api/v1/version'
```

## Учётные данные

| Учётные данные | Поля |
|---|---|
| Токен доступа | Отправляется как `Authorization: token …`. |

Адрес: имя хоста (`forgejo.lan`) или `host:port`. Опции: протокол (по
умолчанию HTTP — поставьте перед ним обратный прокси с TLS для всего, кроме
LAN), порт (3000), проверка сертификата и таймаут запроса (15 с).

Проверено на Forgejo 9.0 (по исходникам официального API и определениям
Swagger, общим с Gitea).
