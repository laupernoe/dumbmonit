# Nginx Proxy Manager

Менеджер прокси: хосты, конфигурацию которых nginx отклонил, отключённые
хосты, и сертификаты, которые хосты предъявляют — до того, как сбой продления
Let's Encrypt превратится в истёкший сайт.

DumbMonit входит в REST API Nginx Proxy Manager (`/api`, на порту его
веб-интерфейса, 81) с собственным пользователем, затем читает прокси-хосты,
хосты перенаправления, 404-хосты (в API называемые dead hosts) и потоки.
Каждый хост сообщает, включён ли он и принял ли nginx его конфигурацию. Хост,
который nginx отклонил, не обслуживается, а веб-интерфейс показывает его лишь
как красную точку.

Сертификаты не читаются из API. `/api/nginx/certificates` отдаёт приватный
ключ импортированных сертификатов и учётные данные DNS-проверки любому
пользователю, которому разрешено просматривать сертификаты. Вместо этого
DumbMonit читает каждый сертификат там, где он обслуживается: TLS-handshake
на порту 443 Nginx Proxy Manager, с именем хоста, который его использует. Это
также измеряет именно тот сертификат, который на самом деле получают
посетители.

## Что отслеживается

Все метрики с префиксом `dumbmonit_npm_`.

| Метрика | Что | Метки |
|---|---|---|
| `version_info` | значение 1 | `version` |
| `hosts`, `hosts_enabled`, `hosts_disabled` | хосты каждого типа | `type`: `proxy`, `redirection`, `dead` (404-хосты), `stream` |
| `hosts_offline` | включённые хосты, конфигурацию которых nginx отклонил | `type` |
| `host_online` | на каждый включённый хост: 0, когда nginx отклонил его конфигурацию | `type`, `host` |
| `host_error_info` | значение 1, для хоста, который nginx отклонил: первая строка ошибки nginx | `type`, `host`, `error` |
| `certificates_checked`, `certificates_read` | сертификаты, привязанные к включённому хосту, и те, что прочитаны на порту HTTPS | |
| `cert_expiry_days` | дней осталось до истечения сертификата, предъявляемого хостом | `host` |

`host` — это первое доменное имя хоста, или `port 9000` для потока.
Отключённые хосты считаются, но не описываются: отключение хоста намеренно, и
его оповещение, если оно было, разрешается. Хосты описываются по одному, до
500 штук, и за одну проверку читается не более 100 сертификатов.

Применяемые [встроенные правила](../alerting/rules.md#reverse-proxies-and-domains):
«Хост Nginx Proxy Manager не в сети», «Сертификат прокси не продлён», плюс
«Устройство недоступно».

## Страница устройства

Панель над графиками читает то, что сохранила проверка; открытие страницы
никогда не запрашивает Nginx Proxy Manager. Она сообщает, что не так, в одном
предложении (хосты, отклонённые nginx, с причиной, сертификаты, близкие к
истечению, сертификаты, которые не удалось прочитать), затем — прокси-хосты,
перенаправления, 404-хосты, потоки и отключённые хосты, затем — сертификаты,
сначала самые близкие к истечению.

## Создание пользователя Nginx Proxy Manager только для просмотра

1. В Nginx Proxy Manager откройте Users и добавьте пользователя для DumbMonit, с собственным адресом электронной почты, например dumbmonit@example.com. Оставьте все роли неотмеченными.

2. В меню этого пользователя откройте Permissions: Item Visibility — All Items; Proxy Hosts, Redirection Hosts, 404 Hosts и Streams — View Only; Access Lists и SSL Certificates — Hidden. Затем задайте его пароль через Change Password в том же меню.

3. SSL Certificates намеренно остаются Hidden: Nginx Proxy Manager отдаёт приватный ключ импортированных сертификатов и учётные данные DNS-проверки любому пользователю, которому разрешён их просмотр. Вместо этого DumbMonit читает каждый сертификат там, где он обслуживается, через TLS-handshake на порту 443 для каждого хоста, у которого он есть.

4. В DumbMonit введите хост Nginx Proxy Manager с портом его веб-интерфейса, например «npm.lan:81», а также email и пароль этого пользователя. Если хосты обслуживаются по HTTPS на другом порту, кроме 443, задайте HTTPS port ниже.

!!! warning
    Хост, конфигурацию которого nginx отклоняет (опечатка в Advanced, отсутствующий файл сертификата), не обслуживается, а Nginx Proxy Manager показывает его в списке лишь как красную точку. Сертификаты Let's Encrypt продлеваются за тридцать дней; тот, что истекает менее чем через четырнадцать дней, — это тот, чьё продление не удалось, и тогда DumbMonit предупреждает.

Item Visibility All Items важен: с Created Items пользователь видит только
хосты, которые сам создал, а их нет ни одного. Пользователь без Proxy Hosts
View Only получает отказ; без Streams, Redirection Hosts или 404 Hosts он
просто не сообщает о них.

DumbMonit хранит токен, который Nginx Proxy Manager выдаёт при входе (действует
сутки), и входит снова, когда он истекает, а не при каждой проверке.

## Учётные данные

| Учётные данные | Поля |
|---|---|
| Email и пароль пользователя | Email и пароль пользователя, созданного выше. |

Адрес: имя хоста или IP с портом веб-интерфейса (`npm.lan:81`), или полный
URL. Опции: протокол (по умолчанию HTTP), порт веб-интерфейса (81), Check the
certificates (включено), HTTPS port (443), проверка сертификата API и таймаут
запроса (10 с).

Проверка сертификата подключается к части адреса с хостом: когда
веб-интерфейс доступен через другой прокси, направьте адрес на сам Nginx
Proxy Manager, либо снимите отметку Check the certificates и наблюдайте за
каждым сайтом с помощью [проверки сертификата TLS](services.md) отдельно.
Wildcard-сертификаты читаются через первый хост, который их использует.
