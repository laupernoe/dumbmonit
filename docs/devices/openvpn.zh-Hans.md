# OpenVPN 服务器 {#openvpn-server}

OpenVPN 的服务器进程暴露自己的控制通道，即**管理接口**：一个本地 TCP 监听器，独立于 VPN 本身，是为监控工具而非 VPN 客户端设计的。DumbMonit 像任何管理客户端一样读取它：服务器的版本、它是否报告自己已连接，以及当前会话中的每个客户端，包括其真实地址和虚拟地址以及流量。绝不会发送任何会改变服务器状态或断开客户端的内容。

客户端在本质上是短暂的 — 进入睡眠的笔记本电脑会直接从下一次读取中消失。DumbMonit 不会尝试记住五分钟前谁已连接；它只报告现在谁已连接，外加客户端数量这一值得随时间绘制图表的指标。

## 监控内容 {#what-it-watches}

所有指标都以 `dumbmonit_openvpn_` 为前缀。

| 指标 | 内容 | 标签 |
|---|---|---|
| `server_info` | 值为 1 | `version` |
| `server_up` | 管理接口报告服务器为 `CONNECTED` 时为 1，否则为 0 | `state` |
| `server_state_age_seconds` | 服务器进入其当前状态以来的时间 | |
| `clients_connected` | 当前在会话中的客户端数量 | |
| `client_bytes_received`、`client_bytes_sent` | 单个客户端的流量（计数器） | `common_name`、`real_address` |
| `client_connected_seconds` | 该客户端会话开始以来的时间 | `common_name`、`real_address` |

`real_address` 从不包含客户端的源端口：它在 NAT 之后每次重新连接都会改变，只会白白增加系列数量。最多 256 个客户端各获得一个详细系列；超出之后 `clients_connected` 仍然精确。

适用的内置规则：**监控项不可达**，当无法建立管理连接本身或密码被拒绝时。

## 监控项页面 {#the-device-page}

图表上方的面板读取探测所存储的内容；打开页面绝不会连接到管理接口。它显示服务器的版本和它是否报告自己已连接、客户端数量，以及当前在会话中的客户端列表及其地址和流量。

## 启用管理接口 {#turn-on-the-management-interface}

1. 管理接口是一个独立的监听器，默认关闭：将以下内容添加到服务器的配置中（server.conf，或 OpenVPN Access Server 的 as.conf，名称不同）并重启它。将其绑定到 DumbMonit 主机可以到达的地址，或绑定到 127.0.0.1，并通过 SSH 隧道或同一台机器上的中继代理访问。

    ```
    management 0.0.0.0 7505
    ```

2. 可选但推荐：管理接口没有自己的账户，只有一个共享密码。将其放入只有 OpenVPN 进程可读的文件中，并作为第三个参数添加。

    ```
    management 0.0.0.0 7505 /etc/openvpn/management-password
    ```

3. 在 DumbMonit 中，输入服务器的地址，例如“vpn.lan”（端口 7505），如果设置了管理密码，也一并输入。

4. DumbMonit 只读：它发送 version、state 和 status 3，从不发送 signal、kill 或 client-kill。它无法断开客户端、更改设置或停止服务器。

!!! warning
    任何能到达管理端口并知道密码的人都可以断开客户端、读取其所有真实 IP 地址，并重新配置正在运行的服务器：不要将其放在公共网络上，请置于只允许 DumbMonit 主机的防火墙规则之后，并设置密码。

## 凭据 {#credentials}

| 凭据 | 字段 |
|---|---|
| 无密码 | 仅适用于在没有密码文件参数的情况下启动的管理接口。 |
| 管理密码 | 由服务器“management”指令的第三个参数设置的共享密码。 |

地址：主机名或 IP，可选 `:port`；默认端口为 7505，这是 OpenVPN 自己文档中的约定，而不是服务器强制执行的标准。选项：端口（7505）和每次交换的超时（10 秒）。

连接被拒绝或没有应答都算作服务器不可达。错误的密码显示为凭据错误；两者都不会在夜里叫醒任何人。连接是纯 TCP：读取的内容都不是机密，但密码（如果设置了）在每次检查时都会以明文穿过网络 — 仅从受信任的网络或通过与服务器在同一台机器上的中继代理访问该接口。
