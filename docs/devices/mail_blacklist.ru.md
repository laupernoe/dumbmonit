# Репутация почтового сервера

Почтовый домен или публичный адрес почтового сервера, проверяемый по чёрным спискам
DNS, которые до сих пор решают, будет ли почта доставлена: Spamhaus,
Barracuda, SpamCop и несколько менее крупных. Для каждого списка, в который
внесён адрес, страница монитора показывает код ответа списка, его опубликованную
причину и прямую ссылку на страницу проверки и удаления.

Введите домен (`example.com`), и DumbMonit проверит адреса его MX-хостов
(записи A и AAAA), адреса самого домена и любые **Extra addresses**, которые вы
добавите (исходящий релей, не являющийся MX). Домен также проверяется по чёрным
спискам доменов. Введите IP-адрес, и будет проверен только этот адрес. Чтобы
следить за целым диапазоном адресов, используйте
[Чёрные списки для диапазона IP](ip_blacklist.md).

## Gmail, Outlook.com и Yahoo

Крупные почтовые провайдеры **не публикуют чёрных списков, к которым можно
обратиться**: их мнение об отправителе остаётся внутренним. DumbMonit не делает
вид, что спрашивает их. Он проверяет то, что влияет на их решение, и даёт ссылки
на их инструменты:

- **Обратный DNS**: у каждого отправляющего адреса должна быть запись PTR, имя
  которой разрешается обратно в тот же адрес (forward-confirmed reverse DNS,
  FCrDNS). Gmail, Outlook.com и Yahoo отклоняют или отправляют в спам почту с
  адресов без неё.
- **SPF и DMARC**: ровно одна запись SPF на домене и запись DMARC в
  `_dmarc.<домен>`. Gmail и Yahoo требуют обе от массовых отправителей.
- **Чёрные списки ниже**, которые читают и их фильтры.

DKIM не проверяется: его селектор выбирает каждый отправитель, и угадать его
нельзя. Страница монитора ведёт на:

| Провайдер | Инструменты |
|---|---|
| Gmail | [Postmaster Tools](https://postmaster.google.com/) (репутация подтверждённого домена), [правила для отправителей](https://support.google.com/a/answer/81126), [форма о проблемах доставки](https://support.google.com/mail/contact/gmail_bulk_sender_escalation) |
| Outlook.com / Hotmail | [SNDS](https://sendersupport.olc.protection.outlook.com/snds/) (данные о репутации по адресам), [политики для отправителей](https://sendersupport.olc.protection.outlook.com/pm/), [форма поддержки отправителей](https://olcsupport.office.com/) (удаление из списков Outlook.com), [портал удаления Microsoft 365](https://sender.office.com/) |
| Yahoo / AOL | [Sender Hub](https://senders.yahooinc.com/), [рекомендации](https://senders.yahooinc.com/best-practices/), [форма поддержки отправителей](https://senders.yahooinc.com/contact/) |

Проверено 16 октября 2026 года. SORBS закрылся в июне 2024 года и не
опрашивается. У каждого списка запрашивается запись `A` в его зоне; список
определяется идентификатором из первого столбца, который параметр **Lists**
принимает для ограничения проверки.

единственному здесь списку, который отвечает для IPv6; остальные показывают их
как не охваченные.

## Резолверы, отказы и тайм-ауты {#resolvers-refusals-and-timeouts}

Списки опрашиваются через DNS, и их ответ зависит от того, **какой резолвер
спрашивает**:

- **Spamhaus отказывает запросам, приходящим через публичные резолверы** (Google
  `8.8.8.8`, Cloudflare `1.1.1.1`, Quad9), через резолверы, пересылающие запросы
  им, или через резолверы без определяемого обратного DNS. Тогда он отвечает
  `127.255.255.254` вместо `NXDOMAIN` (`127.255.255.255`, когда резолвер шлёт
  слишком много запросов, `127.255.255.252` при некорректном запросе или
  неверном ключе DQS). Это похоже на внесение в список, но им не является:
  DumbMonit показывает проверку как **ошибку конфигурации**, а не как
  «в списке», и не отправляет оповещение о сбое.
- **URIBL и SURBL отвечают `127.0.0.1`** резолверам, которым отказывают. Такой
  список отображается как «Refused» (неизвестно), а не как внесение в список.
- **Список, не ответивший вовремя, считается неизвестным, но не чистым.** Только
  `NXDOMAIN` означает «не в списке». Ответ вне `127.0.0.0/8` (резолвер,
  подменяющий `NXDOMAIN` адресом поисковой страницы) тоже считается неизвестным.

Поэтому используйте **собственный рекурсивный резолвер**: Unbound, Knot Resolver,
BIND или PowerDNS Recursor, разрешающие имена от корневых серверов (а не
пересылающие запросы публичному резолверу), и укажите его адрес в поле
**Resolver**, если это не системный резолвер. Pi-hole или AdGuard Home перед
Unbound работают; перед `1.1.1.1` — нет.

Или создайте бесплатную учётную запись [Spamhaus Data Query Service](https://www.spamhaus.com/data-access/free-data-query-service/)
(некоммерческое использование, небольшой объём) и введите её ключ как учётные
данные: тогда Spamhaus опрашивается по `<ключ>.zen.dq.spamhaus.net` и
`<ключ>.dbl.dq.spamhaus.net`, которые отвечают через любой резолвер. Ключ
хранится зашифрованным и больше не показывается.

## Темп

Чёрные списки ограничивают, как часто резолвер может их спрашивать, и банят
резолверы, которые их прочёсывают. DumbMonit опрашивает каждый список раз за
**Refresh interval** (по умолчанию 6 часов), не чаще **Queries per second** (по
умолчанию 10) при восьми одновременных запросах, а между проверками при каждой
проверке показывает последний результат повторно, поэтому правила оповещений
видят непрерывный ряд. Проверка выполняется в фоне: первый результат появляется
через несколько секунд после добавления монитора, а изменение адреса, параметра
или ключа сразу запускает новую проверку. Проверка, закончившаяся ошибкой,
повторяется через десять минут.

## Проверка почтового сервера по чёрным спискам

1. Введите домен, для которого вы отправляете почту, например "example.com": DumbMonit проверит адреса его MX и самого домена. Или введите публичный IP-адрес, с которого отправляет сервер. Если почта уходит через релей, не являющийся MX, добавьте его адрес в Extra addresses.

2. Используйте собственный рекурсивный резолвер. Spamhaus отказывает запросам, приходящим через публичные резолверы (Google, Cloudflare, Quad9) или через пересылающий им резолвер, а другие списки их ограничивают: достаточно Unbound, разрешающего имена от корневых серверов. Укажите его адрес в Resolver, если это не системный резолвер.

3. Или создайте бесплатную учётную запись Spamhaus Data Query Service (некоммерческое использование, небольшой объём) и вставьте её ключ как учётные данные: тогда Spamhaus отвечает через любой резолвер.

    ```
    https://www.spamhaus.com/data-access/free-data-query-service/
    ```

4. Чтобы проверить настройку, добавьте монитор для 127.0.0.2, тестового адреса, который вносят в список все чёрные списки: каждый должен показать его как внесённый.

5. Gmail, Outlook.com и Yahoo не публикуют чёрных списков, к которым можно обратиться. DumbMonit вместо этого проверяет то, что они учитывают (обратный DNS, указывающий на адрес, записи SPF и DMARC) и даёт на странице монитора ссылки на их инструменты для отправителей.

!!! warning
    Ответ, в котором Spamhaus отказал (127.255.255.254, публичный резолвер), показывается как ошибка конфигурации, а не как внесение в список, а чёрный список, не ответивший, показывается как неизвестный, а не как чистый. По умолчанию списки опрашиваются каждые 6 часов: более частые запросы ничего не дают и приводят к бану резолверов.

## Что отслеживается {#what-it-watches}

Все метрики имеют префикс `dumbmonit_blacklist_`.

| Метрика | Что | Метки |
|---|---|---|
| `listed_major_lists` | основные списки (Spamhaus ZEN и DBL, Barracuda, SpamCop), в которых числится адрес или домен | |
| `listed_lists` | все списки, в которых числится адрес или домен | |
| `addresses_checked` | проверено адресов | |
| `addresses_listed` | адреса, числящиеся хотя бы в одном списке | |
| `domain_listed` | 1, когда домен числится в списке доменов | |
| `unknown_checks` | проверки без ответа (тайм-аут, отказ) | |
| `check` | один ряд на адрес (или домен) и список: 1 в списке, 0 чисто, −1 нет ответа, −2 отказ, −3 не охвачен | `list`, `subject`, `state`, `code`, `meaning`, `reason` |
| `list_checked`, `list_listed`, `list_unknown` | по спискам: опрошено объектов, в списке, без ответа | `list` |
| `address_info` | значение 1, откуда взят каждый адрес | `address`, `source` (`mx`, `domain`, `input`, `extra`), `mx` |
| `ptr_ok` | 1, когда обратный DNS разрешается обратно в адрес | `address`, `ptr` |
| `mx_hosts` | MX-хосты домена | |
| `spf_records` | записи `v=spf1` на домене (1 — правильно) | |
| `dmarc_records` | записи `v=DMARC1` в `_dmarc.<домен>` | |
| `dmarc_policy_info` | значение 1 | `policy` |
| `mail_auth_missing` | от 0 до 2: SPF отсутствует или продублирован, DMARC отсутствует | |
| `scan_age_seconds`, `scan_duration_seconds`, `scan_running` | показанная проверка: её возраст, сколько она длилась, идёт ли новая | |

Применяемые [встроенные правила](../alerting/rules.md#dns-blocklists): Listed
on a major blocklist, Listed on a blocklist, Mail server reverse DNS
mismatch, SPF or DMARC missing, а также Monitor unreachable, когда резолвер не
отвечает ни на один запрос.

## Страница монитора

Панель читает то, что сохранила проверка; открытие страницы никогда не
опрашивает чёрный список. Она показывает счётчики, затем каждый список с числом
объектов, которые он содержит, затем каждый результат с кодом списка, его
опубликованной причиной и ссылками на страницы проверки и удаления, затем
обратный DNS каждого адреса, SPF и DMARC и инструменты Gmail, Outlook.com и
Yahoo для отправителей.

## Учётные данные

Нет, или ключ Spamhaus DQS (см. выше).

Адрес: домен (`example.com`) или публичный IP-адрес. Параметры: Resolver,
Lists (по умолчанию все), Extra addresses, Refresh interval (6 часов, от 1
до 168), Queries per second (10, от 1 до 50) и Timeout per query (5 с,
от 1 до 30). Частные адреса никогда не проверяются: чёрные списки знают только
публичный Интернет. `127.0.0.2` принимается как тестовый адрес.
