# VMware vSphere

Сервер vCenter и хосты, которыми он управляет, либо отдельный хост ESXi:
хосты, которые перестают отвечать, оставлены в режиме обслуживания или
сообщают о красном здоровье, виртуальные машины и их VMware Tools, хранилища
данных, которые заполняются или становятся недоступными, и тревоги, которые
поднял сам vSphere.

DumbMonit читает vSphere выделенным пользователем, обладающим встроенной
ролью **Read-only**. Он никогда не включает и не выключает ВМ, никогда не
входит в режим обслуживания и никогда не подтверждает тревогу.

Отказ, за которым стоит следить: **хранилище данных, которое заполняется**.
Когда тонко выделенное хранилище данных достигает 100 %, каждая ВМ, которой
нужно в него писать, немедленно ставится на паузу. Тревоги, которые поднимает
vCenter, тоже об этом сообщают, но только тому, у кого открыт клиент.

## Почему Web Services API

DumbMonit говорит с Web Services API vSphere (SOAP, `/sdk`), а не с REST API
(`/api/vcenter/*`): у отдельного хоста ESXi нет REST API, а на vCenter REST
API не сообщает о режиме обслуживания, общем здоровье (`overallStatus`),
состоянии VMware Tools или сработавших тревогах. Единый обзор всего
инвентаря считывается за один проход, страница за страницей, и освобождается
в конце.

Сессия сохраняется от одной проверки до следующей и переоткрывается только
при истечении: vCenter не регистрирует новый вход каждую минуту.

## Что отслеживается

Все метрики с префиксом `dumbmonit_vsphere_`. Значения здоровья следуют
`overallStatus` vSphere: 0 green, 1 yellow, 2 red, 3 gray (неизвестно).

| Метрика | Что | Метки |
|---|---|---|
| `info` | значение 1 | `product` (`vcenter` или `esxi`), `version`, `build` |
| `hosts` | хосты по состоянию соединения: `connected`, `disconnected`, `notResponding` | `state` |
| `host_connection_state` | 0 подключён, 1 отключён администратором, 2 не отвечает | `host` |
| `host_power_state` | 0 включён, 1 в режиме ожидания, 2 выключен, 3 неизвестно | `host` |
| `host_maintenance` | 1 в режиме обслуживания | `host` |
| `host_status` | общее здоровье | `host` |
| `host_cpu_percent`, `host_memory_percent`, `host_memory_bytes`, `host_uptime_seconds` | только подключённые хосты | `host` |
| `vms` | ВМ по состоянию питания: `poweredOn`, `poweredOff`, `suspended` (шаблоны исключены) | `state` |
| `templates` | шаблоны ВМ | |
| `vm_power_state` | 0 включена, 1 выключена, 2 на паузе; не более 1000 ВМ | `vm` |
| `vm_status` | общее здоровье | `vm` |
| `vm_tools_status` | только включённые ВМ: 0 актуальны, 1 старая версия, 2 установлены, но не запущены, 3 не установлены | `vm` |
| `datastores` | хранилища данных | |
| `datastore_capacity_bytes`, `datastore_free_bytes`, `datastore_used_percent` | | `datastore` |
| `datastore_accessible` | 1 доступно, 0 недоступно | `datastore` |
| `datastore_status` | общее здоровье | `datastore` |
| `alarms` | сработавшие неподтверждённые тревоги, по цвету: `red`, `yellow` | `status` |
| `alarms_acknowledged` | сработавшие тревоги, уже подтверждённые | |
| `alarm` | один ряд на каждую неподтверждённую тревогу, значение = её код здоровья, не более 64 | `alarm` (её имя), `entity`, `entity_type`, `status` |
| `scrape_errors` | вызовы, завершившиеся ошибкой при последней проверке | |

Применяемые [встроенные правила](../alerting/rules.md#vmware-vsphere): «Хост
vSphere не отвечает», «Состояние здоровья хоста vSphere критично», «Хост
vSphere оставлен в обслуживании», «Хранилище данных vSphere почти заполнено»,
«Хранилище данных vSphere недоступно», «VMware Tools не запущены на ВМ
vSphere», «Красная тревога vSphere», плюс «Устройство недоступно».

## Страница устройства

Панель над графиками читает то, что сохранила проверка; открытие страницы
никогда не запрашивает vSphere. Сначала она сообщает, что не так (хосты, не
отвечающие, красные тревоги, хранилища данных почти заполненные или
недоступные), затем — хосты с их нагрузкой, хранилища данных с их уровнем
заполнения, и ВМ по состоянию питания.

## Как это проверялось

На симуляторе govmomi `vcsim` 0.56.0, в режимах vCenter и ESXi: вход и
отклонённый пароль, повторное использование и истечение сессии, постраничный
просмотр инвентаря, хост, не отвечающий, хост в режиме обслуживания,
выключенная ВМ и шаблон. Симулятор не поднимает тревог: чтение сработавших
тревог проверено по документированной структуре `AlarmState` Web Services
API.

## Создание пользователя только для чтения в vSphere

1. На vCenter: Administration → Single Sign On → Users and Groups → Users, домен vsphere.local → Add. Назовите пользователя так и дайте ему длинный случайный пароль.

    ```
    dumbmonit
    ```

2. Всё ещё на vCenter: Administration → Access Control → Global Permissions → Add. Выберите этого пользователя, роль Read-only, и отметьте Propagate to children. Read-only видит каждый хост, ВМ, хранилище данных и тревогу, и не может ничего изменить.

3. На отдельном хосте ESXi вместо этого: в клиенте хоста, Manage → Security & users → Users → Add user, с тем же именем. Затем Host → Actions → Permissions → Add user: выберите его, роль Read-only, и отметьте Propagate to all children.

4. В DumbMonit введите адрес vCenter или хоста, например «vcenter.lan» или «esxi1.lan», с именем пользователя как при создании: dumbmonit@vsphere.local на vCenter, dumbmonit на хосте. Когда vCenter управляет хостами, добавьте только vCenter: он сообщает о каждом хосте, ВМ и хранилище данных.

5. DumbMonit только читает, через Web Services API vSphere (/sdk). Он никогда не включает и не выключает ВМ, никогда не входит в режим обслуживания и никогда не подтверждает тревогу.

!!! warning
    Не используйте повторно учётную запись домена единого входа или встроенную учётную запись хоста: роли Read-only выше достаточно для всего, что нужно DumbMonit. vCenter и ESXi по умолчанию используют самоподписанный сертификат: включите «Accept an unverifiable certificate», если хост DumbMonit не доверяет их центру сертификации.

## Учётные данные

| Учётные данные | Поля |
|---|---|
| Имя пользователя / пароль | Выделенный пользователь с ролью Read-only: `dumbmonit@vsphere.local` на vCenter, `dumbmonit` на хосте. |

Адрес: имя хоста или IP (`vcenter.lan`), `host:port`, или полный URL;
завершающий `/sdk` или `/ui` допускается. Опции: порт (443), проверка
сертификата, таймаут запроса (20 с) и сработавшие тревоги (чтение).
