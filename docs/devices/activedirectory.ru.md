# Active Directory

Домен Windows через LDAP, только для чтения: контроллеры домена и кто держит каждую роль FSMO, члены привилегированных групп, политика паролей, подсчет учетных записей и необработанные факты безопасности, которые аудит ищет в первую очередь — учетные записи, открытые для Kerberoasting или AS-REP roasting, неограниченное делегирование, старый пароль krbtgt, компьютеры без LAPS, выпуски Windows вне поддержки.

DumbMonit привязывается с выделенной учетной записью обслуживания, которая является **простым пользователем домена, членом ни одной группы**. В Active Directory каждый аутентифицированный пользователь может прочитать то, что читает DumbMonit; никаких прав администратора не требуется и не должно быть дано. DumbMonit никогда не пишет в директорию, никогда не читает атрибут пароля (из LAPS он читает дату истечения, никогда не пароль) и никогда не просит права репликации, которые раскрыли бы секреты.

Одно устройство охватывает весь домен: наведите его на один контроллер домена и DumbMonit найдет остальные в разделе конфигурации.

## Что LDAP может и не может сказать

LDAP показывает директорию такой, какая она есть, а не журналы того, что в ней произошло. В частности:

- **Репликация.** Запрашиваемый контроллер домена публикует состояние его партнеров входящей репликации (последний успех, последовательные сбои, последняя ошибка) только учетной записи, которая держит право *Monitor active directory replication*. Без него панель говорит *replication status not readable* вместо предположения. Показывается только вид запрашиваемого контроллера домена: чтобы увидеть другой, добавьте его как второе устройство.
- **Не видимо над LDAP**: журналы событий (входы, блокировки по мере того, как они происходят, изменения групп как события), содержание группьовой политики, SYSVOL, зоны DNS и сами хэши паролей.
- **Последние даты входа** поступают из `lastLogonTimestamp`, которые контроллеры домена реплицируют только каждые 9–14 дней: учетная запись, подсчитанная как неактивная, неактивна в течение двух недель.
- **Членство в группе** читается с вложением (правило `LDAP_MATCHING_RULE_IN_CHAIN`), через `member`/`memberOf`. Первичная группа, установленная `primaryGroupID`, не является ссылкой `member` и не видна.

## Как это читает

Две скорости:

- **При каждой проверке** (каждую минуту по умолчанию): соединение и привязка, RootDSE (функциональные уровни, часы, синхронизация), объект домена (политика паролей, квота учетной записи машины), пять ролей FSMO, контроллеры домена из раздела конфигурации, привилегированные группы и их эффективные члены, функция Recycle Bin и TCP соединение к порту LDAP каждого другого контроллера домена.
- **В фоне** каждые `inventory_minutes` (15 по умолчанию): каждая пользовательская и компьютерная учетная запись, только с атрибутами, необходимыми для выводов, на страницах по 500. Перечисление всей директории каждую минуту будет нагружать контроллеры домена впустую.

Первая проверка ждет несколько секунд для инвентаря; на большом домене выводы учета появляются при следующей проверке.

Domain Admins (RID 512), Enterprise Admins (519) и Schema Admins (518) — последние два только в корневом домене леса — и встроенные Administrators, Account Operators, Server Operators, Print Operators и Backup Operators.

## Выводы

Выводы — это необработанные факты — количество объектов и какие — не оценка; [оценка безопасности](../using/security-score.md) устройства взвешивает их. У каждого есть стабильный `id`, серьезность по шкале оценки (низкая, средняя, высокая, критическая, показано на странице как Info, Advisory и Warning), категория, подсчет и до двадцати примеров имен учетных записей. Вывод, который был проверен и не обнаружил ничего, сохраняется с подсчетом 0, поэтому исправленная проблема становится зеленой вместо исчезновения; выводы об учетных записях появляются после завершения первого фонового инвентаря. Они обслуживаются как есть через `GET /api/targets/{id}/ad/findings` и опубликованы как `dumbmonit_ad_finding_count{finding, severity, title}`.

[Встроенные правила](../alerting/rules.md#active-directory), которые применяются:

- **Domain controller unreachable**: еще один контроллер домена домена перестает отвечать на своем порту LDAP на пять минут (Warning). Запрашиваемый охватывается *Device unreachable*.
- **Active Directory bind failed**: контроллер домена отказывает учетной записи обслуживания — истекший пароль, отключенная или заблокированная (Advisory).
- **Privileged group membership changed**: кто-то присоединился или покинул привилегированную группу, вложение включено (Advisory, разрешается через час).
- **Active Directory replication failing**: входящий партнер не работает в течение получаса (Advisory), когда статус репликации читаемый.
- **krbtgt password older than 180 days** (Info).

## Страница устройства

Панель Active Directory показывает домен (уровни функциональности, запрашиваемый контроллер домена, смещение часов), контроллеры домена с их сайтом, ролями и ответствуют ли они, привилегированные группы с их членами, политику паролей и подсчет учетных записей, и таблицу выводов со словами серьезности.

## Создание учетной записи обслуживания только для чтения для DumbMonit

1. Создайте выделенного пользователя для DumbMonit, например svc-dumbmonit, и не добавляйте его ни в какую группу. Простой пользователь домена достаточно: каждый аутентифицированный пользователь может прочитать то, что читает DumbMonit. В PowerShell с модулем Active Directory:

    ```
    New-ADUser -Name svc-dumbmonit -UserPrincipalName svc-dumbmonit@corp.example.com -AccountPassword (Read-Host -AsSecureString 'Password') -Enabled $true
    ```

2. Дайте ему длинный случайный пароль. Если в вашем домене пароли истекают, DumbMonit вызывает Active Directory bind failed в день, когда это происходит.

3. Опционально: чтобы увидеть статус входящей репликации, предоставьте учетной записи право Monitor active directory replication на самом объекте домена. Это не раскрывает никакой пароль и никакой секрет.

    ```
    dsacls "DC=corp,DC=example,DC=com" /G "CORP\svc-dumbmonit:CA;Monitor active directory replication"
    ```

4. LDAPS требует сертификат на каждом контроллере домена; корпоративный центр сертификации (AD CS) выдает его автоматически. Экспортируйте сертификат этого органа в кодировке Base-64 X.509 и вставьте его как сертификат CA ниже.

5. В DumbMonit введите имя одного контроллера домена так, как его называет его сертификат, например "dc1.corp.example.com", и войдите как svc-dumbmonit@corp.example.com. DumbMonit находит других контроллеров домена сам и проверяет, что каждый отвечает.

6. DumbMonit только читает: он никогда не пишет в директорию, и из LAPS он читает дату истечения, никогда не пароль.

!!! warning
    Простой LDAP на порту 389 отправляет пароль учетной записи обслуживания в открытом тексте: DumbMonit отказывает, если вы не отметите Allow plain LDAP, и контроллер домена, требующий подписи LDAP, также отказывает. Используйте LDAPS или StartTLS на порту 389.

Чтобы удержать учетную запись от открытия сеанса где-либо, отклоните ей *Log on locally* и *Log on through Remote Desktop Services* путем Group Policy: привязка LDAP не затрагивается. Не ограничивайте ее с помощью *Log On To* или *Deny access to this computer from the network*: контроллеры домена тогда отказали бы в привязке.

### Наименьшее привилегия, подробно

- Учетной записи не нужна группа, кроме Domain Users, которую имеет каждая учетная запись.
- Не используйте управляемую учетную запись обслуживания (gMSA): она не может выполнить простую привязку LDAP.
- Не предоставляйте *Replicating Directory Changes* (или *All*): это право DCSync, которое раскрывает каждый хэш пароля. DumbMonit никогда не нуждается в этом.
- *Monitor active directory replication* позволяет только читать метаданные репликации (партнеры, последний успех, коды ошибок). Это опционально.

## LDAPS и сертификаты

- **LDAPS (порт 636)** по умолчанию. Каждый контроллер домена домена с корпоративным центром сертификации получает сертификат автоматически; без одного контроллер домена не прослушивает 636. Сертификат должен нести имя, которое использует DumbMonit: введите контроллер домена по его DNS имени, а не по IP адресу, если сертификат не перечисляет адрес.
- **Сертификат CA**: вставьте PEM корневого (или выдающего) органа. Тогда доверяется только этот орган. Без него DumbMonit доверяет общественным корням и хранилищу системы своего контейнера, которые не знают частный корпоративный орган.
- **StartTLS (порт 389)** шифрует так же, после простого приветствия в открытом тексте. Используйте его, когда порт 636 отфильтрован.
- **Примите непроверяемый сертификат** сохраняет соединение зашифрованным, но принимает любой сертификат: кто-то на пути мог выдать себя за контроллер домена и получить пароль учетной записи обслуживания.
- **LDAP channel binding** (`LdapEnforceChannelBinding`) касается привязок NTLM и Kerberos над TLS; простая привязка, которую использует DumbMonit, не затрагивается.

## Учетные данные

| Поле | Значение |
|---|---|
| Имя пользователя | `svc-dumbmonit@corp.example.com`, `CORP\svc-dumbmonit`, или полный DN учетной записи |
| Пароль | пароль учетной записи, зашифрованный и больше никогда не показываемый |

Пустой пароль отклоняется: Active Directory принял бы его как неаутентифицированную привязку без проверки чего-либо.

## Устранение неполадок

- **Сертификат TLS отклонен**: вставьте сертификат органа как сертификат CA и введите контроллер домена по имени, которое его сертификат перечисляет.
- **Привязка отклонена: неправильное имя пользователя или пароль (результат LDAP 49)**: диагностический код контроллера домена переведен — пароль истек, учетная запись отключена, заблокирована или должна изменить пароль при следующем входе.
- **Контроллер домена требует защищенное соединение**: подпись LDAP принуждается; переключитесь на LDAPS или StartTLS.
- **Контроллер домена показывается как не разрешенный**: его имя не разрешается из хоста DumbMonit. Наведите DNS DumbMonit на DNS серверы домена или отметьте *Check every domain controller*. Не разрешенные имена никогда не вызывают оповещение.
- **Статус репликации не читаемый**: предоставьте *Monitor active directory replication* как в шаге 3 или примите, что репликация не показана.
