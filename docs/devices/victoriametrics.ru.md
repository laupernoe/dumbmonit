# VictoriaMetrics и VictoriaLogs

Сами база данных временных рядов и база данных логов: принимают ли они то,
что им отправляют, сколько осталось диска до того, как они перестанут
принимать что-либо, и что они отклоняют.

Два типа устройств делят эту страницу, потому что два продукта делят основу:
`victoriametrics` для однонодовой VictoriaMetrics, и `victorialogs` для
однонодовой VictoriaLogs. Оба публикуют собственное здоровье на `/health` и
`/metrics`, на порту своего API; DumbMonit читает только эти два и ничего
больше. Он никогда не выполняет запрос к вашим данным и никогда не пишет.

Эти серверы редко падают полностью. Они падают *наполовину*: продолжают
отвечать на запросы, и дашборды всё ещё открываются, в то время как каждый
новый образец или строка лога отклоняется, потому что диск пересёк лимит
только для чтения, либо данные пришли с меткой времени за пределами срока
хранения. То, что отправляет им данные (vmagent, Prometheus remote write,
Vector, Fluent Bit, Promtail), повторяет попытку, затем отбрасывает. Эта
страница о том, как увидеть это заранее.

## Что отслеживается

Метрики с префиксом `dumbmonit_victoriametrics_` или `dumbmonit_victorialogs_`.
Суммарные значения — это счётчики: графики и правила превращают их в
скорости.

| Метрика | Что | Метки |
|---|---|---|
| `healthy` | 1, когда `/health` отвечает OK, 0 — когда отвечает чем-то иным | |
| `version_info` | значение 1 | `version` |
| `rows_ingested_total` | принятые образцы (VictoriaMetrics) или строки логов (VictoriaLogs) | |
| `bytes_ingested_total` | принятый объём логов (только VictoriaLogs) | |
| `rows_rejected_total` | всё отклонённое, присутствует всегда, даже при нуле | |
| `rows_rejected_reason_total` | то же, по причине: `big_timestamp`, `small_timestamp`, `too_long_label_value`, `too_many_labels`, `invalid`, `hourly_series_limit`… (VictoriaMetrics); `too_big_timestamp`, `too_small_timestamp`, `too_many_fields`, `too_long_line` (VictoriaLogs) | `reason` |
| `disk_free_bytes`, `disk_total_bytes` | свободное и общее место тома хранения | `path` |
| `disk_free_limit_bytes` | `-storage.minFreeDiskSpaceBytes`: ниже него хранилище переходит в режим «только чтение» | `path` |
| `disk_headroom_percent` | свободное место, оставшееся выше этого лимита, как доля диска | `path` |
| `read_only` | 1, когда хранилище перешло в режим «только чтение» | |
| `data_size_bytes` | данные на диске | |
| `slow_inserts_total`, `rows_added_total` | новые образцы, прошедшие по медленному пути, и все добавленные образцы (только VictoriaMetrics) | |
| `active_series` | ряды, получившие образец за последний час (только VictoriaMetrics) | |
| `http_errors_total` | запросы, ответившие ошибкой | |
| `log_errors_total` | сообщения об ошибках, залогированные сервером | |
| `uptime_seconds`, `memory_resident_bytes` | | |

**Отклонённый образец потерян.** VictoriaMetrics отклоняет образец старше
своего срока хранения или более чем на два дня в будущем, значение метки
длиннее `-maxLabelValueLen`, ряд с числом меток выше `-maxLabelsPerTimeseries`,
и каждый образец нового ряда после достижения `-storage.maxHourlySeries` или
`-storage.maxDailySeries`. VictoriaLogs отклоняет строки за пределами своего
срока хранения и строки с слишком большим числом полей. Клиент обычно не
получает ошибки на это: знает только этот счётчик.

**Медленные вставки** — это образцы, чей ряд VictoriaMetrics пришлось искать
на диске, а не в кэше. Каждый совершенно новый ряд — это одна такая вставка,
поэтому развёртывание вызывает всплеск; доля, остающаяся выше 5 %, означает,
что серверу не хватает памяти для своих активных рядов. Это порог,
указанный в документации VictoriaMetrics.

Применяемые [встроенные правила](../alerting/rules.md#log-and-metrics-servers):
«Хранилище метрик или логов только для чтения», «Хранилище метрик или логов
почти только для чтения», «Сервер метрик или логов нездоров», «Данные
метрик или логов отклонены», «Медленные вставки VictoriaMetrics», плюс
«Устройство недоступно».

## Страница устройства

Панель над графиками читает то, что сохранила проверка; открытие страницы
никогда не запрашивает сервер. Она сообщает, в этом порядке:

1. **Что не так, в одном предложении**: здоровье, хранилище (*Read-only*,
   либо сколько диска осталось выше лимита), данные, отклонённые за
   последние 24 часа, медленные вставки, залогированные ошибки. Каждая
   строка несёт слово, а также цвет.
2. **Что делает сервер**: образцы или строки, принимаемые в секунду,
   активные ряды или принятый объём, данные на диске, время работы.
3. **Что было отклонено за последние 24 часа, по причине**, и свободное
   место каждого пути хранения относительно его лимита «только чтение».

## Дать DumbMonit читать собственное состояние здоровья VictoriaMetrics

1. Ничего устанавливать не нужно: VictoriaMetrics публикует собственное здоровье на /health и /metrics, на порту своего API (по умолчанию 8428). Проверьте с хоста DumbMonit, что оба отвечают.

    ```
    curl http://victoriametrics.lan:8428/health
    curl -s http://victoriametrics.lan:8428/metrics | grep vm_app_version
    ```

2. Если VictoriaMetrics работает с -httpAuth.username и -httpAuth.password, выберите ниже Username / password и введите их. За vmauth или обратным прокси, ожидающим bearer-токен, выберите Bearer token. Если задан -metricsAuthKey, /metrics отвечает только с этим ключом в URL, который DumbMonit не отправляет: вместо этого защитите /metrics базовой аутентификацией выше.

3. В DumbMonit введите адрес сервера, например «victoriametrics.lan» или «http://10.0.0.5:8428». За обратным прокси введите полный URL с префиксом пути. Это покрывает однонодовый сервер; компоненты кластера VictoriaMetrics публикуют другие метрики и не покрываются.

4. DumbMonit читает только /health и /metrics. Он никогда не выполняет запрос к вашим данным и никогда ничего не пишет.

!!! warning
    Свободное место на диске — это то, за чем стоит следить: ниже -storage.minFreeDiskSpaceBytes (по умолчанию 100 МБ) VictoriaMetrics переходит в режим «только чтение» и отклоняет каждый новый образец, продолжая отвечать на запросы, как будто ничего не случилось. DumbMonit показывает запас выше этого лимита и предупреждает ниже 10 %.

## Дать DumbMonit читать собственное состояние здоровья VictoriaLogs {#let-dumbmonit-read-victorialogs-own-health}

1. Ничего устанавливать не нужно: VictoriaLogs публикует собственное здоровье на /health и /metrics, на порту своего API (по умолчанию 9428). Проверьте с хоста DumbMonit, что оба отвечают.

    ```
    curl http://victorialogs.lan:9428/health
    curl -s http://victorialogs.lan:9428/metrics | grep vl_rows_ingested_total
    ```

2. Если VictoriaLogs работает с -httpAuth.username и -httpAuth.password, выберите ниже Username / password и введите их. За vmauth или обратным прокси, ожидающим bearer-токен, выберите Bearer token. Если задан -metricsAuthKey, /metrics отвечает только с этим ключом в URL, который DumbMonit не отправляет: вместо этого защитите /metrics базовой аутентификацией выше.

3. В DumbMonit введите адрес сервера, например «victorialogs.lan» или «http://10.0.0.6:9428». За обратным прокси введите полный URL с префиксом пути.

4. DumbMonit читает только /health и /metrics. Он никогда не выполняет запрос LogsQL и никогда не читает строку лога.

!!! warning
    Свободное место на диске — это то, за чем стоит следить: ниже -storage.minFreeDiskSpaceBytes (по умолчанию 10 МБ) VictoriaLogs переходит в режим «только чтение» и отклоняет каждую новую строку лога. DumbMonit показывает запас выше этого лимита и предупреждает ниже 10 %.

## Учётные данные

| Учётные данные | Поля |
|---|---|
| Без аутентификации | По умолчанию: `/health` и `/metrics` открыты, если вы их не защитили. |
| Имя пользователя / пароль | `-httpAuth.username` и `-httpAuth.password` сервера, либо обратного прокси перед ним. |
| Токен-носитель | Токен, который vmauth или ваш обратный прокси ожидает в `Authorization: Bearer`. |

Адрес: имя хоста или IP (`victoriametrics.lan`, `10.0.0.5`), `host:port`,
или полный URL с префиксом пути за обратным прокси (`https://metrics.lan/vm`).
Опции: протокол (по умолчанию HTTP), порт (8428 или 9428), проверка
сертификата и таймаут запроса (10 с).
