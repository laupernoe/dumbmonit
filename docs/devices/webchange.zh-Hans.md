# 网站变化 {#website-changes}

监控一个网页、或整个网站的*内容*,并在它发生变化时被告知:一个
价格或条款页面、一个文档站点、某个供应商的维护公告、一个公开
公告页面,或你自己网站在一次部署之后的状态。每一次变化都会保留
前后的文本、逐行差异,以及在浏览器可用时,每个版本的一张截图。

被比较的是每个页面的**可见文本**,而不是它的 HTML:脚本、样式、
注释、`noscript`、`svg` 和 `template` 块都会被去掉,空白会被
折叠,每个块(段落、标题、列表项、表格行)会变成一行。同一页面
的一次新构建、一个被重新排序的属性,或一个全新的防缓存资源
名称,都不会造成任何变化;一句被改写的话则会。

## 页面或网站 {#page-or-site}

**页面**(默认)只读取该设备的地址,不做其他任何事。它也可以是
一个纯文本或 JSON 文档,逐行比较。

**网站**会从该地址开始,跟随同一文件夹下的每一个页面
(`https://example.com/docs/intro.html` 会覆盖 `/docs/` 下的
所有内容;**路径前缀**可以选择另一个文件夹)。页面的发现方式:

1. 通过网站的站点地图:`robots.txt` 宣布的那些(`Sitemap:` 行),
   或 `/sitemap.xml`,包括站点地图索引(一层);
2. 如果没有,或站点地图在该文件夹下没有列出任何内容,则逐页
   跟随链接,按广度优先的方式。

只会跟随同源(协议、主机和端口相同)的页面;指向图片、样式表、
脚本、PDF、压缩包和其他文件的链接会按其扩展名被跳过,任何非
HTML 的应答都会被忽略。片段(`#section`)会被去掉,空查询会被
移除,因此一个页面对应一个地址。对于以这种方式发现的页面,会
遵循 `robots.txt`:名为 `DumbMonit` 的分组,否则是 `*` 分组,
支持 `Allow`、`Disallow`、`*` 和 `$`。

这次爬取是有礼貌的:最多同时两个请求,两批之间间隔半秒,
`User-Agent` 为 `DumbMonit/<version>`,每次请求超时 15 秒,每个
页面最多读取 5 MB。它会在达到**最大页数**(默认 25,最多 200)
或十分钟后停止。

## 检查如何进行 {#how-a-check-works}

该设备会像任何其他设备一样被轮询(默认每分钟),但页面只会每
**检查间隔**分钟读取一次(默认 60,范围 5 到 10080)。在此期间,
轮询只会报告上次检查的状态:网站不会每分钟都被访问一次。检查会
在后台运行;同一设备的两次检查绝不会重叠,设备页面上的**立即
检查**会立刻启动一次检查。

第一次检查只会记录**参照版本**:每个页面都会被读取并保存,不会
报告任何内容。从那之后,对于每个页面:

| 情况 | 保留的内容 |
|---|---|
| 文本与上次相同(经过**忽略行**处理后) | 没有新内容;该页面被标记为已检查。 |
| 文本不同 | 一份新快照和一个**已变化**事件,附带新增和删除的行数。 |
| 一个从未见过、或曾经消失后又重新出现的页面 | 一份快照和一个**新增页面**事件。 |
| 该页面应答 404 或 410 | 一个**页面已移除**事件,上次的快照作为"之前"。 |
| 网站范围:一次完整爬取不再能到达某个已知页面 | 同样会产生一个**页面已移除**事件("不再被链接")。因达到**最大页数**或时间限制而停止的爬取,永远不会得出某个页面已消失的结论。 |
| 该页面上的任何其他错误(超时、403、子页面上的 500) | 该错误会显示在该页面上;不产生事件。 |

更改地址、范围、路径前缀或**忽略行**,会让下一次检查变成一个
新的参照版本,而不是把每个页面都报告为已变化。

### 忽略行 {#ignore-lines}

每次访问都会变化的行——一个时钟、一个访客计数器、"5 分钟前
更新"、一句随机引言——会在每次检查时都被报告。**忽略行**保存
正则表达式(Rust `regex` 语法),每行一个或用 `|` 连接;任何匹配
其中之一的文本行,在比较之前都会被去掉。例如:

```
Updated \d+ minutes ago|Visitors: \d+|© \d{4}
```

### 起始页面不可达 {#unreachable-start-page}

当起始页面本身无法读取时(没有应答、连接被拒绝、超时、HTTP
5xx),该设备会被视为**不可达**:轮询失败,"设备不可达"规则
会像对待任何设备一样触发。此时起始页面会在每次轮询时重新尝试,
因此它的恢复会在一分钟内被发现。一个拒绝访问(401、403)的起始
页面会被报告为配置问题,而不是服务中断。该网站其他页面上的错误
只会显示在那些页面上。

只有 DumbMonit 所在主机自己能访问的地址(回环、链路本地、云端
元数据服务)会被拒绝,除非启用了**允许回环和链路本地目标**;
私有局域网地址始终被允许。

## 告警 {#alerts}

内置规则**网站已变化**(`webchange_detected`,信息级别)会在一次
检查发现至少一项变化(已变化、新增或已移除的页面)后触发,并在
下一次没有发现变化的检查时解决。它读取
`dumbmonit_webchange_last_check_changes`;可以像任何其他规则一样
把它关联到某个渠道,或在**告警 → 规则**中提高其严重级别。参见
[内置规则](../alerting/rules.md#website-changes)。

| 指标 | 含义 |
|---|---|
| `dumbmonit_webchange_pages` | 被跟踪的页面数(不含已移除的页面)。 |
| `dumbmonit_webchange_pages_failed` | 被跟踪、但上次读取失败的页面数。 |
| `dumbmonit_webchange_last_check_changes` | 上次检查发现的变化数。 |

这些指标会在首次检查完成后出现。

## 截图 {#screenshots}

DumbMonit 镜像没有浏览器:截图来自一个可选的无头 Chromium,通过
Chrome DevTools 协议驱动。在 `docker-compose.yml` 中把它作为 `browser` 服务添加到 DumbMonit 旁边,
并让服务器指向它:

```yaml
services:
  dumbmonit:
    environment:
      DUMBMONIT_BROWSER_URL: http://browser:9222
  browser:
    image: chromedp/headless-shell:stable
    shm_size: 256m
    restart: unless-stopped
```

然后执行 `docker compose up -d`。没有任何东西发布浏览器的端口:只有
DumbMonit 服务器通过 Compose 网络与它通信。

`DUMBMONIT_BROWSER_URL` 指向该浏览器(任何以
`--remote-debugging-port` 启动的 Chromium,例如
`chromedp/headless-shell`;服务器会读取 `/json/version`,并连接
到该主机名解析出的地址)。

截图只会在某个页面产生新快照时拍摄(参照版本,以及每次变化),
从不在无变化的检查时拍摄:一个 1366 × 900 的窗口,完整页面最多
到 5000 像素,以 JPEG 格式保存。**截图**选项可以为单个设备关闭
它。没有浏览器,或浏览器没有应答时,文本比较照常进行,快照只是
没有图片;设备页面会说明这一点。

浏览器会像访客一样加载页面,并运行其脚本:它显示的内容可能与
DumbMonit 比较的文本(服务器发送的 HTML)不同。

## 存储 {#storage}

每份快照的文本会保存在数据库中(每个页面最多 1 MB);截图是
`/data/webchange/<device id>/` 下的文件。按设备,最近一百次变化
会被保留;一份快照只要仍是某个页面的最新版本、或被某次保留的
变化引用,就会被保留,其余的内容(包括文件)都会在每次检查后
被删除。删除该设备会移除全部这些内容。

## 监控一个网站的变化 {#watch-a-website-for-changes}

以下步骤正是表单旁边提示所展示的内容。

1. 在地址中粘贴要监控的页面,带 http:// 或 https://。若要监控
   整个网站或其某个部分,请粘贴其起始页面,并把"范围"设为
   "网站":同一文件夹下的每个页面都会被跟踪,直到"最大页数"。
2. 每次访问都会变化的行(一个时钟、一个访客计数器、"5 分钟前
   更新")会每次都被报告:请把它们作为正则表达式列在"忽略行"中。
3. 第一次检查只会记录参照版本,不会报告任何内容。从那之后,
   每次检查都会逐页比较可见文本,并为每次变化保留一份前后对比,
   显示在设备页面上;"网站已变化"告警会告知你。
4. 若要为每个版本生成截图,请在 Compose 文件中添加一个无头浏览器服务,
   并让 DumbMonit 指向它,如[截图](#screenshots)所示。

!!! warning "警告"
    只会比较服务器发送的文本:一个完全由 JavaScript 绘制的页面,
    在检查中显示的内容很少甚至没有。登录后才能看到的页面同样
    无法访问。

凭据:无。检查始终在 DumbMonit 服务器上运行:网站监控无法通过
中继代理进行。

## 选项 {#options}

| 选项 | 默认值 | 含义 |
|---|---|---|
| 范围(`scope`) | `page` | `page`:只监控该地址。`site`:同一文件夹下的每个页面。 |
| 最大页数(`max_pages`) | `25` | 网站范围:每次检查最多读取的页面数,1 到 200。 |
| 路径前缀(`path_prefix`) | 该地址所在的文件夹 | 网站范围:只监控路径以此开头的页面(`/docs/`)。 |
| 忽略行(`ignore`) | —— | 正则表达式;匹配的文本行不会被比较。 |
| 截图(`screenshots`) | `true` | 在配置了浏览器时,为每个新版本保留一张截图。 |
| 检查间隔(`check_interval_minutes`) | `60` | 两次检查之间的分钟数,5 到 10080。 |
| 接受无法验证的证书(`insecure_tls`) | `false` | 用于你自己使用自签名证书的站点。 |
| 允许回环和链路本地目标(`allow_private_targets`) | `false` | 访问由 DumbMonit 主机自身提供服务的站点。 |
