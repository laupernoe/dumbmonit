SNMP device

snmp

Switches, routers, UPS, printers, access points: anything that answers SNMP.

Exemples

  • Switch
  • Router
  • NAS
  • UPS
  • Printer

Ce qu'il faut

  • SNMP v1 / v2c (community)The simplest form: one shared word, sent unencrypted.
  • SNMP v3 (user, authentication, privacy)Authenticated and encrypted. Needs a USM user on the device.

Port par défaut: 161

Règles d'alerte livrées 9

  • AvisHigh CPUCPU load sustained above 90%, averaged per device across SNMP, Proxmox and agent sources; clears below 85 %.
  • InfoUnusual CPUCPU load noticeably different from the usual at this time and day of the week (seasonal baseline).
  • AvisDisk almost fullFilesystem 90% full or more, per mount point (SNMP, Proxmox storages and root filesystems); clears below 88 %.
  • AvisFilesystem almost fullAt this rate, the filesystem will be full within four days.
  • AlerteUPS on batteryThe UPS is powering the load from battery.
  • AlerteUPS battery lowThe UPS battery is low or depleted.
Afficher 3 de plus
  • AvisPort accumulating errorsA network port logged more than fifty errors in the last hour: usually a failing cable, a dirty fibre or a duplex mismatch (increase_prometheus(dumbmonit_if_errors_in[1h]) + increase_prometheus(dumbmonit_if_errors_out[1h]); nothing fires during the first hour of a new device, so errors counted before it was added are not reported as new).
  • AvisPort flappingA network port went down and up again more than twice in thirty minutes (changes_prometheus(dumbmonit_if_oper_status[30m])). A port disabled on purpose has no series and never fires.
  • AlerteDevice unreachableNo measurement received for more than three minutes. bottomk by (target) (1, time() - tlast_over_time(dumbmonit_up[7d]))
Étapes de mise en place: Enable SNMP on the device

  1. Open the device's administration interface.

  2. Look for the SNMP section, often under "Network", "Services" or "Administration".

  3. Enable SNMP v2c and note the read-only community ("public" by default on many devices).

  4. If the device filters by address, allow this server's address.

  5. Come back here, enter the address and the community: the rest is detected automatically.

À savoir. A community is not encrypted on the network. On a shared network, prefer SNMP v3, which authenticates and encrypts.

MikroTik RouterOS

mikrotik

RouterOS and RouterBOOT versions behind, CPU, memory, temperatures, fans and power supplies, and errors and link losses on every interface.

Exemples

  • hAP
  • RB5009
  • CCR
  • CRS switch
  • Cloud Hosted Router

Ce qu'il faut

  • Read-only userThe dumbmonit user created above, in the dumbmonit-read group. Sent as HTTP basic authentication.

Port par défaut: 443

Règles d'alerte livrées 2

  • AvisMikroTik CPU highThe router's CPU has stayed above 90 %: routing, the firewall or a script is saturating it. Clears below 80 %.
  • AlerteDevice unreachableNo measurement received for more than three minutes. bottomk by (target) (1, time() - tlast_over_time(dumbmonit_up[7d]))
Étapes de mise en place: Create a read-only user on the router

  1. Open a terminal on the router (WinBox → New Terminal, or SSH with the default account) and create a group that can only read, through the REST API. RouterOS needs all three policies for a REST read: rest-api opens the API, api and read allow the read itself.

    /user group add name=dumbmonit-read policy=read,api,rest-api comment=DumbMonit

  2. Create the user in that group with a long random password of your own. To accept the account only from DumbMonit, add address= followed by the DumbMonit host's address.

    /user add name=dumbmonit group=dumbmonit-read password=REPLACE-WITH-A-LONG-RANDOM-PASSWORD

  3. Turn on the HTTPS web service, which RouterOS ships disabled and without a certificate. Skip this if www-ssl already has one. Otherwise these commands make a certificate on the router itself; then tick "Accept an unverifiable certificate" in the options below.

    /certificate add name=local-ca common-name=local-ca key-usage=key-cert-sign,crl-sign days-valid=3650
/certificate sign local-ca
/certificate add name=https-cert common-name=router.lan days-valid=825
/certificate sign https-cert ca=local-ca
/ip service set www-ssl certificate=https-cert disabled=no

  4. Optional: to be told about new RouterOS versions, let the router check for them at startup and once a day. A read-only user may not start that check, so DumbMonit only reads its result.

    /system scheduler add name=check-for-updates interval=1d start-time=startup on-event="/system package update check-for-updates once"

  5. In DumbMonit, enter the router's address, for example "192.168.88.1", with the dumbmonit user and its password. DumbMonit only sends GET requests to /rest: it never changes a setting, never starts an update and never reboots the router.

À savoir. RouterOS 7.1 or later is required: RouterOS 6 has no REST API. Do not use the default account: its full group can change everything, while dumbmonit-read has no write policy and every change is refused. The www service (plain HTTP) also answers the REST API, but it sends the password in clear with every request.

UniFi Network

unifi

The UniFi network and what it manages: gateways, switches and access points offline or waiting for adoption, firmware updates, WAN and Internet status, clients and alarms, and the last connection of the clients you mark as worth watching.

Exemples

  • UniFi OS console (Dream Machine, Cloud Gateway, Cloud Key)
  • UniFi Network Server (self-hosted)

Ce qu'il faut

  • API key (UniFi OS console)Reads devices, their load and the client count through the official Integration API. Created in Settings → Control Plane → Integrations.
  • View Only accountA local account with the View Only role. Also reads the WAN, Internet and alarm status, and works on a self-hosted server.

Port par défaut: 443

Règles d'alerte livrées 8

  • AvisUniFi device offlineA UniFi device adopted by the controller is offline, isolated or failed to adopt.
  • AlerteUniFi Internet downThe UniFi gateway reports no Internet connection. Without a UniFi gateway the series does not exist and the rule stays silent.
  • AvisUniFi WAN link downA WAN link of the UniFi gateway is down: with two links, redundancy is lost while nothing seems broken. A disabled port has no series.
  • AvisUniFi gateway CPU highThe UniFi gateway's processor has been above 90% for fifteen minutes; clears below 80 %.
  • InfoUniFi device waiting for adoptionA device appeared on the network and waits to be adopted in UniFi.
  • InfoUniFi firmware update availableA firmware update is available for UniFi devices.
Afficher 2 de plus
  • AvisUniFi alarmsUniFi logged critical events or raised alarms in the last 24 hours. Only read with a View Only account.
  • AlerteDevice unreachableNo measurement received for more than three minutes. bottomk by (target) (1, time() - tlast_over_time(dumbmonit_up[7d]))
Étapes de mise en place: Create a read-only access in UniFi Network

  1. On a UniFi OS console (Dream Machine, Cloud Gateway, Cloud Key), you can create an API key: in UniFi Network, Settings → Control Plane → Integrations → Create API Key. Name it after DumbMonit and copy it now: it is shown only once. The key reads devices, their load and the number of clients through the official Integration API.

  2. For the WAN, Internet and alarm status, and on a self-hosted UniFi Network Server, use a local account with the View Only role instead: Settings → Admins & Users → Create New. Name it as follows, give it a long random password, restrict it to local access, and set its UniFi Network role to View Only. View Only reads everything and can change nothing.

    dumbmonit

  3. In DumbMonit, enter the address of the console or server, for example "unifi.lan" (port 443 on a console) or "unifi.lan:8443" for a self-hosted server, and paste the key or the account. If the network is not the default site, set the Site option to the short name shown in the address bar after /manage/ or /network/.

  4. DumbMonit only reads. It never restarts, adopts, upgrades or provisions a device, and never acknowledges an alarm.

À savoir. Do not use the owner account or a UI.com cloud account: a leaked password would open every console linked to it. Keep two-factor authentication off for this local View Only account only, since a monitoring server cannot type a code. Consoles use a self-signed certificate by default: enable "Accept an unverifiable certificate" unless you installed your own. UniFi knows every client that ever connected, most of them phones passing by: only those named, reserved on a fixed IP, or noted in UniFi are watched for staleness by default, to avoid an alert for every visitor's phone. List more in the Clients to watch option, or enter all.

Tailscale

tailscale

The devices of a tailnet through the Tailscale API: servers offline, node keys about to expire, devices awaiting approval, clients to update, and each device's last connection.

Exemples

  • Tailscale tailnet
  • Subnet routers
  • Exit nodes

Ce qu'il faut

  • OAuth clientRecommended: a client limited to the devices:core:read scope, which can change nothing.
  • API access tokenWorks too, but carries every right of the user who created it and expires after 90 days at most.

Port par défaut: 443

Règles d'alerte livrées 5

  • AvisTailscale device offlineA Tailscale device that must stay online (a tagged device by default) has been disconnected for more than 15 minutes (dumbmonit_tailscale_device_offline_seconds and on (target, device) dumbmonit_tailscale_device_watched > 0).
  • AvisTailscale node key expiringA Tailscale device's node key expires in less than 14 days: it will leave the tailnet until someone signs it in again.
  • AvisTailscale device awaiting approvalA device joined the tailnet and awaits approval: approve it if it is expected, remove it otherwise.
  • InfoTailscale client updateA Tailscale device that must stay online runs a client with an update available (dumbmonit_tailscale_device_update_available and on (target, device) dumbmonit_tailscale_device_watched > 0).
  • AlerteDevice unreachableNo measurement received for more than three minutes. bottomk by (target) (1, time() - tlast_over_time(dumbmonit_up[7d]))
Étapes de mise en place: Create a read-only OAuth client for DumbMonit

  1. In the Tailscale console (login.tailscale.com), open Settings > Trust credentials (formerly OAuth clients) and generate an OAuth client with only the devices:core:read scope. It lists the devices and can change nothing.

  2. Copy the client ID and the client secret (tskey-client-…), shown once. In DumbMonit, enter api.tailscale.com as address and paste them as Client ID and Client secret. Leave the Tailnet option empty: the tailnet of the client is read.

À savoir. Only tagged devices (servers, subnet routers, exit nodes) are expected to stay online: a phone or a laptop that sleeps is not an outage. Name the devices to watch in the Devices to keep online option, or enter all. Every device of the tailnet appears in the Devices table below with its last connection, watched or not; a phone that travels can go days without one, so raise Device staleness for those.

OpenVPN server

openvpn

An OpenVPN server through its management interface: version, whether it reports itself connected, and every client currently in session with its addresses and traffic.

Exemples

  • OpenVPN Access Server
  • A plain openvpn --server on Linux
  • pfSense or OPNsense OpenVPN (management enabled)

Ce qu'il faut

  • Management passwordThe shared password set by the third argument of the server's "management" directive.

Aucun compte nécessaire.

Port par défaut: 7505

Règles d'alerte livrées 1

  • AlerteDevice unreachableNo measurement received for more than three minutes. bottomk by (target) (1, time() - tlast_over_time(dumbmonit_up[7d]))
Étapes de mise en place: Turn on the management interface

  1. The management interface is a separate listener, off by default: add this to the server's configuration (server.conf, or the OpenVPN Access Server's as.conf under a different name) and restart it. Bind it to an address the DumbMonit host can reach, or to 127.0.0.1 and reach it through an SSH tunnel or a relay agent on the same machine.

    management 0.0.0.0 7505

  2. Optional but recommended: the management interface has no account of its own, only a shared password. Put one in a file readable by the OpenVPN process alone and add it as a third argument.

    management 0.0.0.0 7505 /etc/openvpn/management-password

  3. In DumbMonit, enter the server's address, for example "vpn.lan" (port 7505), and the management password if one is set.

  4. DumbMonit only reads: it sends version, state and status 3, never signal, kill or client-kill. It cannot disconnect a client, change a setting or stop the server.

À savoir. Anyone who reaches the management port and knows the password can disconnect clients, read all of their real IP addresses, and reconfigure the running server: keep it off the public network, behind a firewall rule that allows only the DumbMonit host, with a password set.
