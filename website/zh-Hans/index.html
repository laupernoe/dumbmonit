Alpha 版，面向早期测试者 Apache 2.0，没有付费版

一切正常吗？一秒钟就知道。

极简的自托管监控，从家庭实验室到小型企业。一个容器，输入一个 IP 地址，不到一分钟就能看到有用的图表和告警。

$ mkdir dumbmonit && cd dumbmonit
$ curl -fsSLO https://raw.githubusercontent.com/laupernoe/dumbmonit/main/docker-compose.yml
$ docker compose up -d

然后打开 http://localhost:8080 并创建第一个账户。镜像支持 amd64（arm64 稍后提供）：ghcr.io/laupernoe/dumbmonit。

试用在线演示 在 GitHub 上查看 阅读安装指南

这是 Alpha 版本（当前发布版为 0.1.0-alpha.7）。DumbMonit 每天都在作者自己的网络中运行，但 HTTP API 尚未冻结，数据库结构仍在变动，目前也不保证跨结构变更的升级。部分集成只在测试实例上验证过，没有经过多年的生产硬件考验，下文已作标注。欢迎试用，并告诉我们哪里出了问题。

添加任何东西，只有一种方式

设备列表（监控项）以行或磁贴形式显示，带有产品图标。从五十多种监控类型中选择一种，阅读其中说明需要在设备上做哪些准备的提示，只填写该类型需要的字段。SNMP 配置文件根据设备的 sysObjectID 自动选择，其余使用默认值。

网络与防火墙

  • SNMP v1、v2c 和 v3交换机、路由器、NAS、UPS、打印机。接口与错误、主机资源、UPS 电池、打印机耗材；内置七个配置文件，自动应用。
  • OPNsense 仅测试实例网关的往返时间与丢包、pf 状态表、VPN 隧道、DHCP 租约、CARP、待处理更新。只读 API 密钥。
  • 网络发现扫描一个 CIDR 网段，一次性添加所有应答的设备。

服务器与虚拟化平台

  • Proxmox VE节点、虚拟机与容器、存储、HA、Ceph、ZFS、集群法定人数，以及每个客户机最近一次备份的时间。
  • Proxmox Datacenter Manager 仅测试实例控制台仍能连到哪些集群和备份服务器，整个环境一页看全，各站点的失败任务。
  • 服务器硬件（Redfish） 仅参考模拟数据风扇、对照硬件自身阈值的温度、电源与冗余、驱动器、内存、事件日志。已对照 DMTF 模拟数据验证，尚未在真实的 iDRAC、iLO 或 Supermicro 主板上测试。
  • 安装代理的机器Linux 和 Windows，macOS 与 FreeBSD 为预览版。详见下文。
  • Active Directory通过 LDAP 使用普通无特权账户监控 Windows 域：FSMO 角色、特权组，以及域审计最先查看的事项——可被 Kerberoast 的账户、过旧的 krbtgt 密码、未部署 LAPS 的计算机。

存储与备份

  • Proxmox Backup Server每台机器 30 天的备份日历、附带日志的失败任务、验证与 GC 任务、数据存储填满预测。
  • Synology DSM卷、存储池、磁盘与 SMART、温度、Hyper Backup 和 Active Backup for Business（含最近一次成功的时间），以及 Drive 和 Photos 套件状态。
  • TrueNAS 仅测试实例丢了一块盘但仍在提供数据的存储池，并指明是哪块盘；scrub、配额、快照、复制、SMART。
  • Plakar 备份通过代理获取每个仓库最近一次快照的时间与结果。

服务与应用

  • 可用性检查HTTP(S)（状态码、关键字、JSON 路径和证书）；TCP 端口；DNS 记录；ping；TLS 证书到期；NTP 偏移与层级。历史条、响应时间、可用率。
  • 应用会话SMTP、PostgreSQL、MySQL 和 MariaDB、MQTT 与 WebSocket：真实登录或握手，因此“在线但拒绝你”不会被报告为“在线”。
  • 心跳cron 任务或备份脚本调用一个保密 URL；一旦它不再调用，你就会收到通知。兼容 Uptime Kuma 的推送方式。
  • Docker 容器通过代理获取状态、健康、重启次数、镜像存在时间和可用更新。可选在维护窗口内重启与更新。
  • 网站健康与 SEO宕机、报错、空白页、缺少预期文本、noindex、屏蔽一切的 robots.txt、响应缓慢，以及标题、描述或规范 URL 的变化（连续两次检查确认）。会跟随重定向，因此 http 跳转到 https 不会误报。还能发现几乎变空的页面、语言标签和重定向的变化，每项检查都可单独开关，确认次数也可调整。网站可设置类别（电商、博客、Web 应用、展示站）和平台（WordPress、Shopify、Wix…）。为数百个网站而设计：探测会分散在检查间隔内，并对每个域名保持礼貌，CSV 导入会把网站归入文件夹。
  • 网站变更检测监视某个页面，或按 sitemap 爬取的整个网站，检测其可见文本的变化：变化前后的文本、逐行差异，以及（如有）截图。
  • GitLab 与 Forgejo/Gitea自托管 Git 平台上的 Sidekiq 队列、CI/CD runner、计划任务和数据库迁移。一个普通的访问令牌即可确认实例在线。
  • Nginx 与 Apache通过 stub_status 或 mod_status 获取活跃/空闲的 worker 或连接数、请求与字节速率。无需账户。
  • Proxmox Mail Gateway 仅测试实例Postfix 队列与最久的滞留邮件、今日已过滤的邮件、隔离区大小、杀毒和反垃圾邮件特征库的存在时间。
已在真实监控项上使用 仅测试实例基于专门安装的真实软件副本构建和验证，尚未在生产环境中连续运行数周

每种类型在监控项文档中都有专门页面，说明它具体读取什么、需要做哪些准备。演示监控类型无需任何硬件即可生成数据。

没有噪音的告警

安装后即启用有用的规则。工作重心在于发送更少、更有价值的消息。

  • 依赖关系

    把交换机声明为其下游设备的父级。它宕机时你只收到一条通知，而不是三十条；其余显示为“被上级抑制”。

  • 按主机分组

    阵列降级的 NAS 每个周期只发一条消息，而不是每块磁盘一条。提醒、升级、确认、暂停提醒、按设备忽略和清除已解决的历史，全部内置。

  • 先学习的基线

    无需调阈值的异常检测：168 个时段，对应一周中的每个小时。前 14 天保持静默，只显示它本来会触发什么。

  • 预报

    “该文件系统将在四天内写满”会作为预报列出，与当前已经出问题的内容分开。

  • 维护与通知策略

    一次性或每周的窗口、滞后、抖动保持、安静时段、批量发送和每小时上限，让糟糕的一夜不会变成两百条推送。

为不支持 SNMP 的设备准备的代理

一个小型二进制程序，把 CPU、内存、磁盘、网络、服务和运行时间推送到服务器，机器提供时还包括温度、风扇、SMART 和 ZFS 存储池。由它主动连接服务器，而不是反过来：机器上无需开放任何端口。

# 界面会自动为你填入令牌
curl -sSL http://server:8080/install.sh | sh -s -- \
  --token=dmon_xxx --url=http://server:8080

Windows 上可从 /install.ps1 获取 PowerShell 脚本。代理也提供镜像：ghcr.io/laupernoe/dumbmonit-agent。

  • Linux已支持x86_64 和 aarch64，systemd 或 OpenRC。Docker 容器和操作系统健康状况（更新、待重启、失败的单元）。
  • Windows已支持x86_64，作为 Windows 服务安装。通过 smartctl 获取 SMART。
  • macOS预览版launchd，Apple silicon 和 Intel；二进制文件随每个版本发布。尚未在真实硬件上运行。
  • FreeBSD预览版rc.d，x86_64，ZFS 存储池。尚未在真实硬件上运行。
  • 远程站点，仅出站连接

    在中继模式下，代理从自己所在的网络——第二个站点、客户的网络或 NAT 后的 VPS——运行服务器的探测（SNMP、Proxmox、HTTP…），无需任何入站连接：不用 VPN，也不用开放端口。监控远程站点

面向你的服务对象的状态页

公开页面位于 /s/<name>：服务分组，含 90 天的每日历史、30 天和 90 天可用率、事件与维护公告、采用双重确认的电子邮件订阅者、RSS、可用于 README 的徽章、适合内网的精简嵌入，以及可选的 90 天日历和响应时间图表，还有横幅后可选的场景：约五十种可选，从城市天际线（威尼斯、巴黎、东京、纽约…）和世界奇观，到瑞士地标（马特洪峰、日内瓦大喷泉、卢塞恩、伯尔尼、西庸城堡）。天空随服务状态变化，每个场景在服务宕机或恢复时都有各自的反应。瑞士场景配有 SBB 风格的车站时钟、翻页式告警牌、8 月 1 日的烟花、日内瓦的“Escalade”汤锅庆典和冬季雪景。

只有你选择的标签会离开服务器。设备名称、地址和类型绝不会出现在页面、徽章或邮件中。

文档中的状态页

  • 墙面模式

    只显示概览，全屏，适合房间里的显示器：一幅动态场景（默认是有埃菲尔铁塔和 DumbMonit 鸽子的巴黎屋顶，也可选其他许多场景），其天气随告警变化；为长时间开着的屏幕准备的 OLED 主题；以及墙面音乐 — Spotify Connect 能把屏幕变成音箱。

  • 安全评分

    可选：启用后，主机、Proxmox、Synology、OPNsense、网站和 Active Directory 旁边会显示 A–F 等级，并附有失败项的报告和具体的修复步骤。仅供参考，不是审计。

  • 账户

    管理员、操作员（处理告警，不改配置）和查看者角色，可选的 TOTP 二次验证，审计日志，以及基于 OpenID Connect 的单点登录（Authentik、Authelia、Keycloak、Pocket ID…），默认关闭账户注册。

  • 与你正在运行的系统和平共处

    /metrics、/federate 和兼容 Prometheus 的端点，让现有的 Grafana 可以读取 DumbMonit 的数据。

  • 开放且有文档的 API

    所有路由都列在 /api/openapi.json（OpenAPI 3.1）中：带作用域的令牌（dmt_…，只读或可写），可设置过期、限制网络来源，并有速率限制。API 参考

  • 通过 MCP 使用的助手

    面向 Claude Code、Claude Desktop、ChatGPT、VS Code 或 Cursor 的 27 个工具：读取状态、设备、告警、指标和代理；具有写权限的令牌还可以静音、确认告警、添加设备或重启容器。密钥绝不会返回。连接助手

  • 在手机上

    查看状态、确认告警、开启维护窗口。可安装到主屏幕，刻意不提供离线模式：它绝不会显示昨天的状态。

小到让你忘了它的存在

一个内置 Web 界面的 Rust 二进制程序，由它在同一镜像内启动的 VictoriaMetrics 时序数据库，以及用于配置的 SQLite。没有数据库容器，没有消息队列。

1一个容器，一个卷
~130 MB内存，在 15 台设备上实测
1架构：amd64（arm64 稍后提供）
0所需的 capability
  • 内存数字是整个容器（含时序数据库）在小型实例上的占用。数据库的缓存预算默认为 256 MB，面对数百台主机时可以调高。
  • 以非 root 用户在只读文件系统上运行，并丢弃所有 capability。Ping 监控通过 sysctl 实现，不需要 NET_RAW。
  • 探测和通知渠道跟随的重定向不会离开已配置的主机，渠道不能指向 DumbMonit 自身，webhook 请求头作为加密的密钥保存。
  • 凭据静态加密（AES-256-GCM）。备份只有一个文件，使用你选择的口令加密，可先试运行，再恢复到全新实例上。
  • 已经在运行 VictoriaMetrics？把 DUMBMONIT_VM_URL 指向它，内置的就不会启动。

与其他工具的比较

DumbMonit 面向只需照看十台机器和三台交换机的人。成熟的工具各有所长，下面说明各自更适合的场景。

Zabbix

成熟，经受过数千台主机的检验，几乎什么都有模板，支持分布式代理和长期支持版本。但它也需要数据库服务器、Web 前端，以及学习监控项、触发器和模板的时间。

大型设备群，或者今天就需要这种深度时，选 Zabbix。想要一秒钟的答案，并能接受集成较少、项目还很年轻时，选 DumbMonit。

Prometheus 与 Grafana

指标领域的标准：庞大的 exporter 生态、PromQL，以及适用于任何东西（包括你自己的应用）的仪表盘。整套组件需要你自己组装和维护：Prometheus、Alertmanager、exporter、仪表盘和规则。

DumbMonit 已经把这套组装好，并提供 /metrics、/federate 和兼容 Prometheus 的端点，因此两者可以并存。

Uptime Kuma

一款精致、非常流行的可用性监控工具，监控类型、通知服务更多，社区也更大。它从外部检查服务；不会读取交换机的端口、虚拟化平台的客户机或 NAS 的磁盘。

DumbMonit 在设备指标之外，也包含 Kuma 风格的检查和兼容推送的心跳。如果你只需要可用性检查，Uptime Kuma 是更成熟的选择。

全部开源

Apache 2.0，包括依赖项：任何不在 OSI 认可许可证下的依赖，CI 都会失败。没有任何功能为付费版保留，因为根本没有付费版。

本网站没有统计分析，没有 cookie，也没有第三方请求。

仍在变动的部分

  • HTTP API 尚未冻结，数据库结构在各个 Alpha 版本之间仍会变化。
  • OPNsense、TrueNAS、Proxmox Datacenter Manager 和 Mail Gateway 需要来自真实长期运行环境的反馈。Redfish 需要真实的管理控制器。
  • macOS 和 FreeBSD 代理需要有人在真实硬件上运行。
  • 界面为英文；语言选择器已提供另外 8 种语言（德语、西班牙语、法语、意大利语、两种变体的葡萄牙语、俄语、简体中文），目前部分已翻译（文档提供相同的语言），并且欢迎通过 pull request 提交翻译。
  • 接下来做什么由 GitHub issues 决定，更新日志记录了变更内容。
