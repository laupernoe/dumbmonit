Proxmox VE

proxmox

Nodes, virtual machines, containers, storage and backups of a Proxmox server or cluster.

Примеры

  • Proxmox server
  • Proxmox cluster

Что понадобится

  • API token (recommended)No expiry and no session opened: the right choice for monitoring.
  • Username / passwordOpens a two-hour session, renewed automatically. Use it only if tokens are not an option.

Порт по умолчанию: 8006

Встроенные правила оповещений 32

  • ПредупреждениеBackup too oldNo successful Proxmox VE backup for more than seven days.
  • ПредупреждениеVM or container stoppedThe guest was running within the last two hours and has been stopped for five minutes == 1).
  • ПредупреждениеVM or container CPU highA guest has used more than 90 % of its allocated cores for fifteen minutes. The notification names the guest, nextcloud (202).
  • ПредупреждениеVM or container memory highA guest has used more than 95 % of its memory for ten minutes.
  • ПредупреждениеVM or container disk almost fullThe root disk of a guest is more than 90 % full: containers always, VMs only when the QEMU guest agent reports usage.
  • ПредупреждениеGuest lockedA VM or container has been locked for six hours: an interrupted backup or migration left the lock behind and no operation can run on the guest, not even the next backup.

Шаги настройки: Create a read-only user and token in Proxmox VE

  1. Open a shell on any node (in the web UI: select the node, then Shell; or SSH) and create a user reserved for monitoring. It needs no password: the token is what logs in.

    pveum user add dumbmonit@pve --comment "DumbMonit monitoring"

  2. Create a role with only the privileges the collector uses: Sys.Audit (nodes, cluster, HA, disks and SMART, ZFS, certificates, package versions, subscription), Datastore.Audit (storages and backup archives), VM.Audit (VMs, containers, snapshots) and VM.GuestAgent.Audit (what the QEMU guest agent reads inside a VM: disk usage, operating system, IP addresses). None of them can change anything.

    pveum role add DumbMonit --privs "Datastore.Audit Sys.Audit VM.Audit VM.GuestAgent.Audit"

  3. Give the user that role on the whole cluster.

    pveum aclmod / -user dumbmonit@pve -role DumbMonit

  4. Create the user's API token. Privilege separation is off, so the token simply inherits the user's rights.

    pveum user token add dumbmonit@pve monitor --privsep 0

  5. The command prints a table with full-tokenid and value. Copy full-tokenid into DumbMonit's Token ID field and value (the UUID) into its Secret field. The secret is shown once: if it is lost, remove the token and create a new one.

    dumbmonit@pve!monitor

  6. Optional, to count pending updates and pending security fixes: Proxmox guards that list with Sys.Modify. Grant it on /nodes only; without it the collector skips the list silently.

    pveum role add DumbMonitUpdates --privs Sys.Modify
pveum aclmod /nodes -user dumbmonit@pve -role DumbMonitUpdates

  7. On an older Proxmox, VM.GuestAgent.Audit may not exist yet and the command above is refused with invalid privilege: the guest-agent calls are then covered by VM.Monitor, which Proxmox VE 9 removed in turn. Use whichever your version knows.

    pveum role add DumbMonit --privs "Datastore.Audit Sys.Audit VM.Audit VM.Monitor"

  8. Prefer the web UI? The same steps live under Datacenter → Permissions: Users, Roles, Add → User Permission, then API Tokens with "Privilege Separation" unticked.

  9. In DumbMonit, enter the address of any node (port 8006 by default).

Обратите внимание. Do not reuse the account you log in with: a leaked token would then control the whole cluster. The DumbMonit role above can only read. Proxmox also uses a self-signed certificate by default: if the connection is refused for that reason, tick "Accept an unverifiable certificate" in the options.

Proxmox Datacenter Manager

pdm

The console over several clusters: which instances it reaches, their failed tasks, its health.

Примеры

  • Proxmox Datacenter Manager

Что понадобится

  • API token (recommended)No expiry and no session opened: the right choice for monitoring.

Порт по умолчанию: 8443

Встроенные правила оповещений 6

  • ТревогаFederated instance unreachableThe datacenter console cannot reach one of the Proxmox VE clusters or backup servers it federates. The notification names the instance and its product.
  • ИнфоFederated instance behindAn instance runs an older version than another instance of the same product in the same estate. Compared between instances, never against what Proxmox publishes.
  • ПредупреждениеTask failed on a federated instanceAt least one task failed on a federated instance in the review window.
  • ПредупреждениеDatacenter console disk almost fullThe root filesystem of the datacenter console is more than 90 % full: full, the console stops recording what it collects.
  • ПредупреждениеDatacenter console certificate expiringA certificate of the datacenter console expires in less than fourteen days.
  • ИнфоDatacenter console updates pendingMore than twenty package updates are pending on the datacenter console.
Шаги настройки: Create a read-only user and token in Proxmox Datacenter Manager

  1. In the console, open Configuration → Access Control → Users and click Add. Name the account as follows and leave the password empty: the token is what logs in.

    dumbmonit@pdm

  2. Still under Access Control, open API Tokens → Add, pick that user and name the token "monitor". The console shows the secret once: copy it now.

    dumbmonit@pdm!monitor

  3. Give both the user and the token the Auditor role on / (the top of the tree, so the whole estate). Auditor carries System.Audit, Resource.Audit and Access.Audit, and can change nothing. A token never has more rights than its user, so the permission is granted twice: Permissions → Add → User Permission, then again with API Token Permission.

  4. Copy the token id into DumbMonit's Token ID field and the secret into its Secret field.

  5. In DumbMonit, enter the console address, for example "dc.lan" or "dc.lan:8443".

Обратите внимание. Do not reuse the account you log in with: a leaked token would then control every cluster the console federates at once. The Auditor role can only read. The console also uses a self-signed certificate by default: if the connection is refused for that reason, tick "Accept an unverifiable certificate" in the options. Two items need more than Auditor and are simply skipped without it: the per-instance metric collection status, and the update summary of the federated instances.

VMware vSphere

vsphere

vCenter and ESXi hosts: hosts not responding or left in maintenance, VMs and their VMware Tools, datastores filling up, and the alarms vSphere raised.

Примеры

  • vCenter Server
  • ESXi (standalone host)

Что понадобится

  • User name / passwordThe dedicated user with the Read-only role. On a vCenter, include the domain.

Порт по умолчанию: 443

Встроенные правила оповещений 8

  • ТревогаvSphere host not respondingA vSphere host is not responding to vCenter. A host disconnected on purpose (1) does not fire.
  • ТревогаvSphere host health redvSphere reports a host's overall health as red. Gray means unknown and does not fire.
  • ИнфоvSphere host left in maintenanceA vSphere host has been in maintenance mode for a day: its VMs were moved away and it may have been forgotten there.
  • ПредупреждениеvSphere datastore almost fullA vSphere datastore is 90% full or more; clears below 85 %.
  • ТревогаvSphere datastore inaccessibleA vSphere datastore is inaccessible: the VMs stored on it cannot run.
  • ИнфоvSphere VM tools not runningVMware Tools are installed but not running in a powered-on VM: the guest may be hung. VMs without Tools do not fire.

Шаги настройки: Create a read-only user in vSphere

  1. On a vCenter: Administration → Single Sign On → Users and Groups → Users, domain vsphere.local → Add. Name the user as follows and give it a long random password.

    dumbmonit

  2. Still on the vCenter: Administration → Access Control → Global Permissions → Add. Pick that user, the Read-only role, and tick Propagate to children. Read-only sees every host, VM, datastore and alarm, and can change nothing.

  3. On a standalone ESXi host instead: in the host client, Manage → Security & users → Users → Add user, with the same name. Then Host → Actions → Permissions → Add user: pick it, the Read-only role, and tick Propagate to all children.

  4. In DumbMonit, enter the address of the vCenter or of the host, for example "vcenter.lan" or "esxi1.lan", with the user name as created: dumbmonit@vsphere.local on a vCenter, dumbmonit on a host. When a vCenter manages the hosts, add only the vCenter: it reports every host, VM and datastore.

  5. DumbMonit only reads, through the vSphere Web Services API (/sdk). It never powers a VM on or off, never enters maintenance mode and never acknowledges an alarm.

Обратите внимание. Do not reuse the single sign-on domain account or the host's built-in account: the Read-only role above is all DumbMonit needs. vCenter and ESXi use a self-signed certificate by default: enable "Accept an unverifiable certificate" unless the DumbMonit host trusts their certificate authority.

XCP-ng / XenServer

xcpng

An XCP-ng or XenServer pool through XAPI: hosts disabled or offline, VMs and their power state, storage repositories filling up, and a high-availability pool that can no longer survive the host failures it is set to tolerate.

Примеры

  • XCP-ng 8.2 and 8.3
  • XenServer / Citrix Hypervisor

Что понадобится

  • User name and passwordThe dumbmonit account, registered on the pool as a subject with the read-only role.

Порт по умолчанию: 443

Встроенные правила оповещений 5

  • ТревогаXCP-ng host offlineA host of the XCP-ng pool no longer answers the coordinator.
  • ПредупреждениеXCP-ng SR almost fullAn XCP-ng storage repository is more than 90% full.
  • ТревогаXCP-ng HA-protected VM downA VM protected by the pool's high availability is halted.
  • ПредупреждениеXCP-ng pool HA overcommittedThe pool no longer has a plan to survive the host failures it is set to tolerate.
  • ТревогаDevice unreachableNo measurement received for more than three minutes. bottomk by (target) (1, time() - tlast_over_time(dumbmonit_up[7d]))
Шаги настройки: Give DumbMonit a read-only XAPI account

  1. XAPI only accepts accounts other than its built-in superuser once the pool uses external authentication. If the pool is already joined to Active Directory, create a dumbmonit account there and go to step 3.

  2. Otherwise, create a local account with a long random password on every host of the pool, then turn on PAM authentication once, from the pool coordinator. Until a role is given, the account can call nothing.

    useradd -M -s /sbin/nologin dumbmonit
passwd dumbmonit
xe pool-enable-external-auth auth-type=PAM service-name=pam

  3. On the pool coordinator, register the account as a subject, then give that subject the built-in read-only role, with the UUID the first command prints.

    xe subject-add subject-name=dumbmonit
xe subject-role-add uuid=SUBJECT_UUID role-name=read-only

  4. In DumbMonit, enter the address of the pool coordinator, for example "xcp01.lan", with that user name and password. Add the pool once: the coordinator reports every host, VM and storage repository. A pool member answers with the coordinator's address, which DumbMonit then follows.

  5. DumbMonit only reads, through XAPI's JSON-RPC interface (/jsonrpc): it never starts, stops or migrates a VM and never changes a storage repository or the pool's high availability.

Обратите внимание. Never give DumbMonit the superuser password of the hosts: with the read-only role, a leaked password cannot change anything. XCP-ng and XenServer ship a self-signed certificate: enable "Accept an unverifiable certificate" unless the DumbMonit host trusts the certificate the pool presents.

Nutanix AHV (Prism Central)

nutanix

Nutanix clusters through the v4 API of Prism Central: hosts degraded or in maintenance, AHV VMs and their power state, storage containers filling up, and unresolved alerts by severity.

Примеры

  • Prism Central pc.2024.3 or later
  • AHV clusters

Что понадобится

  • User name and passwordThe dumbmonit local user of Prism Central, with the Prism Viewer role.

Порт по умолчанию: 9440

Встроенные правила оповещений 4

  • ТревогаNutanix host degradedPrism reports a Nutanix host as degraded.
  • ПредупреждениеNutanix storage container almost fullA Nutanix storage container is more than 90% full.
  • ТревогаNutanix critical alertsPrism Central reports one or more unresolved critical alerts.
  • ТревогаDevice unreachableNo measurement received for more than three minutes. bottomk by (target) (1, time() - tlast_over_time(dumbmonit_up[7d]))
Шаги настройки: Create a read-only user in Prism Central

  1. In Prism Central, open Admin Center > IAM > Identities and add a local user with a long random password, named as follows.

    dumbmonit

  2. Under Admin Center > IAM > Authorization Policies, create a policy with the built-in Prism Viewer role, for all entities, and assign it to that user. Prism Viewer reads clusters, hosts, VMs, storage containers and alerts, and changes nothing.

  3. In DumbMonit, enter the address of Prism Central, for example "prism-central.lan", with that user name and password. One Prism Central reports every cluster registered to it.

  4. DumbMonit only reads the v4 API (clustermgmt, vmm and monitoring, version 4.0): it never powers a VM on or off, never resolves an alert and never changes a storage container.

Обратите внимание. The v4 API is served by Prism Central pc.2024.3 or later; a cluster managed by Prism Element alone, or by an older Prism Central, is not supported. Prism Central ships a self-signed certificate: enable "Accept an unverifiable certificate" unless the DumbMonit host trusts its certificate authority.

Kubernetes / k3s

kubernetes

A cluster through its API: nodes not ready or under pressure, pods crash looping or stuck pending, workloads missing replicas, volume claims never bound.

Примеры

  • k3s
  • kubeadm cluster
  • k0s
  • MicroK8s
  • Talos

Что понадобится

  • Service account tokenThe token of the dumbmonit service account, read from its dumbmonit-token Secret.

Порт по умолчанию: 6443

Встроенные правила оповещений 8

  • ТревогаKubernetes node not readyA node is not Ready: its kubelet no longer reports, and its pods will be evicted.
  • ПредупреждениеKubernetes node under pressureA node reports memory, disk or PID pressure.
  • ТревогаKubernetes pod crash loopingA container is in CrashLoopBackOff and still restarting: at least two restarts in 15 minutes (max_over_time(dumbmonit_k8s_pod_crashlooping[10m]) and on (target, namespace, pod) increase_prometheus(dumbmonit_k8s_pod_restarts[15m]) >= 2; the state disappears for a moment at each restart attempt). Containers killed by a node or runtime restart (exit 137, 143 or 255, not OOMKilled) do not count, so a reboot does not look like a crash loop.
  • ПредупреждениеKubernetes pod stuck pendingA pod has been Pending for fifteen minutes: no node can take it, or a volume or an image it needs does not come.
  • ПредупреждениеKubernetes pod restartingA pod restarted more than five times in the last hour without being in CrashLoopBackOff (increase_prometheus(dumbmonit_k8s_pod_restarts[1h]) unless on (target, namespace, pod) max_over_time(dumbmonit_k8s_pod_crashlooping[10m]) > 0).
  • ПредупреждениеKubernetes workload missing replicasA Deployment, StatefulSet or DaemonSet has fewer available replicas than it asks for.

Шаги настройки: Create a read-only service account for DumbMonit

  1. Create a service account, a ClusterRole that can only get and list nodes, pods, workloads, volume claims and events, and bind them together. The role reads no Secret and no ConfigMap. On a k3s server, run each command as sudo k3s kubectl.

    kubectl create serviceaccount dumbmonit -n kube-system
kubectl create clusterrole dumbmonit-read --verb=get,list --resource=nodes,pods,persistentvolumeclaims,events,deployments.apps,statefulsets.apps,daemonsets.apps
kubectl create clusterrolebinding dumbmonit-read --clusterrole=dumbmonit-read --serviceaccount=kube-system:dumbmonit

  2. Give it a token that does not expire: a Secret of type service-account-token, which Kubernetes fills in. Then print the token, and the cluster CA in base64.

    echo '{"apiVersion":"v1","kind":"Secret","metadata":{"name":"dumbmonit-token","namespace":"kube-system","annotations":{"kubernetes.io/service-account.name":"dumbmonit"}},"type":"kubernetes.io/service-account-token"}' | kubectl apply -f -
kubectl -n kube-system get secret dumbmonit-token -o jsonpath='{.data.token}' | base64 -d
kubectl -n kube-system get secret dumbmonit-token -o jsonpath='{.data.ca\.crt}'

  3. In DumbMonit, enter the address of the API server, for example "https://k3s.lan:6443". Paste the token as Service account token and the base64 CA as Cluster CA certificate: only that CA is then trusted. One API server reports the whole cluster.

Обратите внимание. The API server's certificate only lists its own names and addresses: an address it does not list fails verification. Use one it lists (a node IP address, or a name added with --tls-san on k3s), or tick Accept an unverifiable certificate.
