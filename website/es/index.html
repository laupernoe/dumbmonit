Alpha, para probadores tempranos Apache 2.0, sin edición de pago

¿Todo bien? Sábelo en un segundo.

Monitorización autoalojada y sencilla, del homelab a la pequeña empresa. Un contenedor, una dirección IP que escribir, gráficos y alertas útiles en menos de un minuto.

$ mkdir dumbmonit && cd dumbmonit
$ curl -fsSLO https://raw.githubusercontent.com/laupernoe/dumbmonit/main/docker-compose.yml
$ docker compose up -d

Después abre http://localhost:8080 y crea la primera cuenta. Imagen para amd64 (arm64 más adelante): ghcr.io/laupernoe/dumbmonit.

Probar la demo en vivo Ver en GitHub Leer la guía de instalación

Esto es una alpha (la versión actual es la 0.1.0-alpha.7). DumbMonit funciona a diario en la red de su autor, pero la API HTTP no está congelada, el esquema de la base de datos aún cambia y todavía no hay garantía de actualización entre cambios de esquema. Varias integraciones solo han visto instancias de prueba, no hardware de producción con años encima; están marcadas más abajo. Pruébalo y cuéntanos qué falla.

Una sola forma de añadir cualquier cosa

La lista de dispositivos (Monitores) muestra filas o mosaicos con iconos de producto. Elige un tipo de monitor entre más de cincuenta, lee el aviso que indica qué preparar en el dispositivo y rellena solo los campos que ese tipo necesita. Los perfiles SNMP se eligen a partir del sysObjectID del dispositivo; los valores por defecto hacen el resto.

Red y cortafuegos

  • SNMP v1, v2c y v3Switches, routers, NAS, SAI, impresoras. Interfaces y errores, recursos del host, batería del SAI, consumibles de impresora; incluye siete perfiles que se aplican solos.
  • OPNsense Solo instancia de pruebaGateways con tiempo de ida y vuelta y pérdidas, la tabla de estados de pf, túneles VPN, concesiones DHCP, CARP, actualizaciones pendientes. Clave de API de solo lectura.
  • Descubrimiento de redBarre un rango CIDR y añade de una vez todo lo que responde.

Servidores e hipervisores

  • Proxmox VENodos, VM y contenedores, almacenamiento, HA, Ceph, ZFS, quórum del clúster y la antigüedad de la última copia de seguridad de cada invitado.
  • Proxmox Datacenter Manager Solo instancia de pruebaQué clústeres y servidores de copias alcanza aún la consola, todo el parque en una sola página, tareas fallidas en cada sitio.

  • Máquinas con el agenteLinux y Windows, con macOS y FreeBSD en vista previa. Más abajo.
  • Active DirectoryUn dominio Windows por LDAP con una cuenta normal, sin privilegios: roles FSMO, grupos privilegiados y lo primero que busca una auditoría de dominio — cuentas kerberoastables, contraseña antigua de krbtgt, equipos sin LAPS.

Almacenamiento y copias de seguridad

  • Proxmox Backup ServerUn calendario de copias de 30 días por máquina, tareas fallidas con sus registros, tareas de verificación y GC, previsión de llenado del datastore.
  • Synology DSMVolúmenes, pools, discos y SMART, temperatura, Hyper Backup y Active Backup for Business con la antigüedad del último éxito, además del estado de los paquetes Drive y Photos.
  • TrueNAS Solo instancia de pruebaEl pool que perdió un disco y sigue sirviendo datos, con el disco señalado; scrubs, cuotas, snapshots, replicación, SMART.
  • Copias de PlakarAntigüedad y resultado del último snapshot por repositorio, a través del agente.

Servicios y aplicaciones

  • Comprobaciones de disponibilidadHTTP(S) con estado, palabra clave, ruta JSON y certificado; puerto TCP; registros DNS; ping; caducidad del certificado TLS; desfase y stratum de NTP. Barra de historial, tiempo de respuesta, disponibilidad.
  • Sesiones de aplicaciónSMTP, PostgreSQL, MySQL y MariaDB, MQTT y WebSocket: un inicio de sesión o handshake real, para que un «arriba pero te rechaza» no se dé por «arriba».
  • HeartbeatsUna tarea cron o un script de copia llama a una URL secreta; cuando deja de llamar, te enteras. Compatible con el push de Uptime Kuma.
  • Contenedores DockerEstado, salud, reinicios, antigüedad de la imagen y actualizaciones disponibles, a través del agente. Reinicio y actualización opcionales dentro de una ventana de mantenimiento.
  • Salud web y SEOCaída, error, página en blanco, texto esperado ausente, noindex, un robots.txt que lo bloquea todo, respuestas lentas y cambios de título, descripción o URL canónica (confirmados por dos comprobaciones seguidas). Se siguen las redirecciones, así que http a https no es una falsa alarma. También detecta una página que queda casi vacía, cambios en las etiquetas de idioma y en las redirecciones; cada comprobación se puede activar o desactivar y el número de confirmaciones es ajustable. Los sitios reciben una categoría (comercio electrónico, blog, aplicación web, escaparate) y una plataforma (WordPress, Shopify, Wix…). Pensado para cientos de sitios: las sondas se reparten a lo largo del intervalo y son discretas con cada dominio, y una importación CSV los ordena en carpetas.
  • Detección de cambios webVigila una página, o un sitio entero rastreado desde su sitemap, por si cambia su texto visible: texto antes/después, un diff por líneas y, cuando es posible, capturas de pantalla.
  • GitLab y Forgejo/GiteaColas de Sidekiq, runners de CI/CD, tareas programadas y migraciones de base de datos en una forja Git autoalojada. Un token de acceso normal basta para comprobar que la instancia está activa.
  • Nginx y ApacheWorkers o conexiones activos/inactivos, tasas de peticiones y de bytes, mediante stub_status o mod_status. No hace falta cuenta.
  • Proxmox Mail Gateway Solo instancia de pruebaColas de Postfix y el mensaje atascado más antiguo, correo filtrado hoy, tamaños de cuarentena, antigüedad de las firmas de antivirus y antispam.

Alertas sin ruido

Las reglas útiles están activas nada más instalar. El esfuerzo se dedica a enviar menos mensajes, y mejores.

  • Dependencias

    Declara un switch como padre de lo que cuelga de él. Cuando cae recibes una sola notificación, no treinta; las demás aparecen como «Suprimida por el padre».

  • Agrupadas por host

    Un NAS cuya matriz se degrada envía un mensaje por ciclo, no uno por disco. Recordatorios, escalado, reconocimiento, posponer, ignorar por dispositivo y borrado del historial resuelto vienen incluidos.

  • Líneas base que primero aprenden

    Detección de anomalías sin umbral que ajustar: 168 intervalos, uno por cada hora de la semana. Permanece en silencio durante sus primeros 14 días y solo muestra lo que habría disparado.

  • Previsiones

    «Este sistema de archivos se llenará en cuatro días» aparece como previsión, aparte de lo que está roto ahora mismo.

  • Mantenimiento y una política de notificaciones

    Ventanas puntuales o semanales, histéresis, retención de flapping, horas de silencio, agrupación y un tope por hora, para que una mala noche no se convierta en doscientas notificaciones.

Un agente para lo que no habla SNMP

Un binario pequeño que envía al servidor CPU, memoria, discos, red, servicios y tiempo de actividad, además de temperaturas, ventiladores, SMART y pools ZFS cuando la máquina los expone. Es él quien llama al servidor, nunca al revés: no hay que abrir ningún puerto en la máquina.

# la interfaz rellena el token por ti
curl -sSL http://server:8080/install.sh | sh -s -- \
  --token=dmon_xxx --url=http://server:8080

Para Windows se sirve un script de PowerShell en /install.ps1. El agente también existe como imagen, ghcr.io/laupernoe/dumbmonit-agent.

  • LinuxCompatiblex86_64 y aarch64, systemd u OpenRC. Contenedores Docker y salud del SO (actualizaciones, reinicio pendiente, unidades fallidas).
  • WindowsCompatiblex86_64, instalado como servicio de Windows. SMART mediante smartctl.
  • macOSVista previalaunchd, Apple silicon e Intel; binarios adjuntos a cada versión. Aún no probado en hardware real.
  • FreeBSDVista previarc.d, x86_64, pools ZFS. Aún no probado en hardware real.
  • Sitios remotos, solo conexiones salientes

    En modo relay, un agente ejecuta las sondas del servidor (SNMP, Proxmox, HTTP…) desde su propia red — una segunda sede, la red de un cliente o un VPS tras NAT — sin nada entrante: ni VPN ni puertos que abrir. Monitorizar un sitio remoto

Páginas de estado para quienes dependen de tus servicios

Páginas públicas en /s/<name>: grupos de servicios con 90 días de historial diario, disponibilidad a 30 y 90 días, anuncios de incidentes y mantenimiento, suscriptores por correo con doble confirmación, RSS, badges para un README, una vista compacta para incrustar en una intranet, un calendario de 90 días y gráficos de tiempo de respuesta opcionales, y una escena opcional tras el banner: unas cincuenta para elegir, desde skylines de ciudades (Venecia, París, Tokio, Nueva York…) y maravillas del mundo hasta símbolos suizos (el Cervino, el Jet d’Eau, Lucerna, Berna, Chillon). El cielo sigue el estado de tus servicios y cada escena reacciona a su manera cuando algo cae o se recupera. Las suizas llevan un reloj de estación al estilo SBB, un panel de alertas de láminas, fuegos artificiales el 1 de agosto, el caldero de la Escalade y nieve en invierno.

Solo salen del servidor las etiquetas que tú eliges. Los nombres, direcciones y tipos de los dispositivos nunca aparecen en la página, en un badge ni en un correo.

Páginas de estado en la documentación

  • Modo pared

    Solo el boletín, a pantalla completa, para un monitor en la sala: una escena viva (por defecto una azotea de París con la Torre Eiffel y las palomas de DumbMonit, u otra entre muchas) cuyo tiempo sigue tus alertas, un tema OLED para una pantalla encendida durante días y música de pared — Spotify Connect convierte la pantalla en un altavoz.

  • Puntuación de seguridad

    Cada dispositivo compatible recibe una puntuación de 0 a 100 y una nota de la A a la F a partir de las comprobaciones de buenas prácticas del propio fabricante, al estilo PingCastle: categoría, severidad, evidencia, remediación y una página de Seguridad ordenada de peor a mejor.

  • Cuentas

    Roles de administrador, operador (gestiona alertas, no cambia la configuración) y lector, segundo factor TOTP opcional, registro de auditoría y inicio de sesión único con OpenID Connect (Authentik, Authelia, Keycloak, Pocket ID…), con la creación de cuentas desactivada por defecto.

  • Se lleva bien con lo que ya usas

    /metrics, /federate y un endpoint compatible con Prometheus permiten que un Grafana existente lea los datos de DumbMonit.

  • API abierta y documentada

    Todas las rutas tras /api/openapi.json (OpenAPI 3.1): tokens con ámbito (dmt_…, de lectura o escritura) que pueden caducar, limitarse a una red y tienen límite de peticiones. Referencia de la API

  • Un asistente por MCP

    27 herramientas para Claude Code, Claude Desktop, ChatGPT, VS Code o Cursor: leer estado, dispositivos, alertas, métricas y agentes; con un token de escritura también puede silenciar, reconocer, añadir un dispositivo o reiniciar un contenedor. Los secretos nunca salen. Conectar un asistente

  • En el móvil

    Consulta el estado, reconoce una alerta, inicia una ventana de mantenimiento. Se puede instalar en la pantalla de inicio y, a propósito, sin modo sin conexión: nunca muestra el estado de ayer.

Tan pequeño que te olvidas de que está

Un binario de Rust con la interfaz web integrada, la base de datos de series temporales VictoriaMetrics lanzada por ese mismo binario dentro de la misma imagen, y SQLite para la configuración. Sin contenedor de base de datos, sin cola de mensajes.

1Contenedor, un volumen
~130 MBde RAM, medidos con 15 dispositivos
1Arquitectura: amd64 (arm64 más adelante)
0Capabilities necesarias
  • La cifra de memoria es la del contenedor entero, base de datos de series temporales incluida, en una instancia pequeña. El presupuesto de caché de la base de datos es de 256 MB por defecto y puede ampliarse para cientos de hosts.
  • Se ejecuta como usuario no root sobre un sistema de archivos de solo lectura, sin ninguna capability. Los monitores de ping funcionan mediante un sysctl, no con NET_RAW.
  • Las redirecciones que siguen las sondas y los canales de notificación nunca salen del host configurado, un canal no puede apuntar al propio DumbMonit y las cabeceras de los webhooks se guardan como secretos cifrados.
  • Las credenciales se cifran en reposo (AES-256-GCM). Las copias de seguridad son un único archivo, cifrado con una frase de contraseña que tú eliges, restaurable en una instancia nueva tras una prueba en seco.
  • ¿Ya tienes VictoriaMetrics? Apunta DUMBMONIT_VM_URL hacia ella y la integrada no se inicia.

Cómo se compara

DumbMonit es para quien vigila diez máquinas y tres switches. Las herramientas consolidadas son excelentes en lo suyo; aquí está dónde encaja mejor cada una.

Zabbix

Maduro, probado con miles de hosts, con una plantilla para casi todo, proxies distribuidos y versiones de soporte a largo plazo. También exige un servidor de base de datos, un front end web y tiempo para aprender ítems, triggers y plantillas.

Elige Zabbix para flotas grandes o si necesitas esa profundidad hoy. Elige DumbMonit si quieres la respuesta en un segundo y puedes vivir con menos integraciones y un proyecto joven.

Prometheus y Grafana

El estándar en métricas: un enorme ecosistema de exporters, PromQL y paneles para lo que sea, incluidas tus propias aplicaciones. La pila la montas y mantienes tú: Prometheus, Alertmanager, exporters, paneles y reglas.

DumbMonit trae ese montaje ya hecho y expone /metrics, /federate y un endpoint compatible con Prometheus, así que ambos pueden convivir.

Uptime Kuma

Un monitor de disponibilidad pulido y muy popular, con más tipos de monitor, más servicios de notificación y una comunidad mayor. Comprueba los servicios desde fuera; no lee los puertos de un switch, los invitados de un hipervisor ni los discos de un NAS.

DumbMonit incluye comprobaciones al estilo Kuma y heartbeats compatibles con push, junto a las métricas de los dispositivos. Si lo único que necesitas son comprobaciones de disponibilidad, Uptime Kuma es la opción más madura.

Código abierto, todo

Apache 2.0, dependencias incluidas: la CI falla ante cualquier dependencia que no tenga una licencia aprobada por la OSI. Ninguna función se reserva para una edición de pago, porque no existe.

Este sitio no tiene analítica, ni cookies, ni peticiones a terceros.

Lo que aún se mueve

  • La API HTTP no está congelada y el esquema de la base de datos sigue cambiando entre alphas.
  • OPNsense, TrueNAS, Proxmox Datacenter Manager y Mail Gateway necesitan informes de instalaciones reales y de larga duración. Redfish necesita un controlador de gestión real.
  • Los agentes de macOS y FreeBSD necesitan que alguien los ejecute en hardware real.
  • La interfaz está en inglés; el selector de idioma ya ofrece otros 8 (alemán, español, francés, italiano, portugués en dos variantes, ruso, chino simplificado), traducidos en parte (la documentación está disponible en los mismos idiomas), y las traducciones están abiertas en Weblate.
  • Lo que se construye después se decide en los issues de GitHub, y el changelog dice qué ha cambiado.

Cuéntanos qué falla

Un dispositivo que lee mal, una alerta que te despertó sin motivo, una página que te confundió: cada informe mejora la siguiente alpha. Las peticiones de soporte para nuevos dispositivos también son bienvenidas.
