Synology DSM

synology

Volumes, pools, disk health, temperature, Hyper Backup and Active Backup jobs, Synology Drive and Photos.

Esempi

  • DiskStation
  • RackStation

Cosa serve

  • DSM account

Porta predefinita: 5001

Regole di avviso incluse 15

  • AvvisoSynology disk SMART warningDSM no longer reports this disk's SMART status as normal.
  • AllarmeSynology disk failedDSM reports the disk as crashed or failed.
  • AllarmeSynology disk bad sectorsThe disk's bad-sector count exceeds the threshold set in DSM.
  • AvvisoSynology disk bad sectors growingNew unreadable sectors appeared in the last 24 hours (delta(dumbmonit_synology_disk_unc_count[24h])).
  • AvvisoSynology SSD wearing outAn SSD has less than 10 % of its rated life left; clears above 12 %.
  • AllarmeSynology volume degradedA volume is degraded or crashed: its redundancy is gone.
Mostra altre 9
  • AllarmeSynology storage pool degradedA storage pool or SSD cache is degraded or crashed: a disk failed and the redundancy is gone or rebuilding.
  • AvvisoSynology volume almost fullA volume is 90 % full or more; clears below 88 %.
  • AvvisoSynology temperature highA disk is above 55 °C, or DSM raised its own temperature warning; clears below 52 °C.
  • AvvisoSynology memory highMemory usage of the NAS above 95 %; clears below 90 %.
  • AllarmeActive Backup task failedThe last run of an Active Backup for Business task failed, or backed up only part of its devices. The notification names the task.
  • AvvisoActive Backup too oldNo successful Active Backup for Business run for this task for more than two days. The series does not exist for a task that has never succeeded; "Active Backup task failed" speaks then.
  • InfoActive Backup task disabledThe task has no schedule, or its continuous backup is paused: it will not back up anything until someone runs it.
  • AvvisoActive Backup device overdueA device has gone longer without a successful Active Backup for Business run than its own rhythm allows, off-days excluded).
  • AllarmeActive Backup device failingThe last two or more attempts of a device failed; a cancelled run counts as neither.
Passaggi di configurazione: Create a monitoring account in DSM

  1. In DSM, open Control Panel → User & Group → User and click Create. Name the account as follows and give it a long password that is used nowhere else.

    dumbmonit

  2. Join groups: tick administrators. DSM only answers the storage, volume and disk SMART calls to that group; without it the NAS shows as alive but says nothing about its disks. The next two steps take back everything else.

  3. Assign shared folder permissions: No access on every shared folder. Assign application permissions: Deny everything except DSM, plus Active Backup for Business if you want its tasks read. Skip the quota and speed limit pages.

  4. Two-step verification must stay off for this account: no automated monitor can type a one-time code. If Control Panel → Security → Account enforces it, restrict the rule to groups this user is not in, or exempt it.

  5. Backup packages are read only while they are installed and running: DSM does not advertise a stopped package's API at all, so Hyper Backup tasks then go quiet instead of failing, and a NAS that only receives backups (Hyper Backup Vault) has no tasks of its own to show. Active Backup for Business additionally answers only an account allowed to use it (Active Backup for Business → Settings → Privileges); otherwise untick DumbMonit's "Watch Active Backup for Business" option to stop asking.

  6. In DumbMonit, enter the NAS address (HTTPS, port 5001 by default), then this account's user name and password.

Attenzione. The administrators group is required by DSM's storage API, not by DumbMonit. That is why this account gets no shared folder, no application and a password used nowhere else: it can read the NAS, not touch your files.

TrueNAS

truenas

Pool health, the failing disk, scrubs, snapshots, replication and TrueNAS's own alerts.

Esempi

  • TrueNAS SCALE
  • TrueNAS Community Edition

Cosa serve

  • API keyThe key TrueNAS shows once when it is created, as "3-AbCd…".

Porta predefinita: 443

Regole di avviso incluse 13

  • AllarmeNAS pool degradedZFS no longer calls a pool healthy. A degraded pool still serves its data, which is exactly why nobody notices until the next disk fails. The device page names the disk.
  • AvvisoNAS disk errorsDisks of a pool have reported read, write or checksum errors since the last zpool clear.
  • AvvisoNAS pool almost fullA pool is more than 85 % full. ZFS slows down well before it is full. Clears at 80 %.
  • AllarmeNAS scrub found errorsThe last scrub of a pool found damaged data.
  • InfoNAS scrub overdueA pool has not completed a scrub in more than 45 days. Absent after a resilver, which erases the record of the last scrub.
  • AllarmeNAS disk failed its SMART testA SMART self-test in a disk's log failed. A disk never tested has no series.
Mostra altre 7
  • AvvisoNAS disk too hotA disk is above 55 °C. Clears at 50 °C.
  • AvvisoNAS dataset near its quotaA dataset has used more than 90 % of its quota: at 100 % its writes fail while the pool still has room. No quota, no series.
  • AvvisoNAS replication failedAn enabled replication task is in error: the copy on the other side is getting older.
  • AvvisoNAS snapshot task failedAn enabled periodic snapshot task is in error.
  • AvvisoNAS snapshots staleAn enabled periodic snapshot task has not run for more than eight days: a task that stops running does not fail, it goes quiet.
  • AvvisoTrueNAS alert raisedTrueNAS itself has raised an alert of level ERROR or above. Its own sentence is on the device page.
  • AvvisoNAS service stoppedA service set to start with the NAS is stopped. A service switched off on purpose has no series.
Passaggi di configurazione: Create an API key for DumbMonit in TrueNAS

  1. In the web interface: Credentials → Groups → Add. Name the group as follows and give it the Local Administrator privilege.

    dumbmonit

  2. Why Local Administrator and not Read-Only Administrator: TrueNAS wired its read-only roles into its WebSocket API only. Over the REST API DumbMonit uses, a read-only key is refused on every single call. DumbMonit itself only ever reads: it never starts a scrub, a SMART test, an update or a replication.

  3. Credentials → Users → Add. Name the account as follows, make dumbmonit its primary group, and leave shell access, sudo and SSH off: none of them is needed.

    dumbmonit

  4. Create the key: Credentials → Users → API Keys → Add, pick the dumbmonit user and give the key a name. TrueNAS shows the key only once: copy it. On TrueNAS 24.10 the path is the user menu at the top right → API Keys → Add, and a key belongs to no user.

  5. In DumbMonit, enter the NAS address, for example "nas.lan", and paste the key. Keep HTTPS: TrueNAS revokes a key it ever receives over plain HTTP from another machine.

Attenzione. This key can change anything on the NAS: TrueNAS offers no read-only key over its REST API. Treat it like the password of an account that can erase your pools, keep it for DumbMonit alone, and revoke it from the same page if it leaks. TrueNAS also ships with a self-signed certificate: if the connection is refused for that reason, tick "Accept an unverifiable certificate" in the options.

Unraid

unraid

An Unraid server through its GraphQL API: array stopped, disks disabled or with errors, parity checks, cache pool usage, containers that should be running.

Esempi

  • Unraid 7
  • Unraid 6.12 with Unraid Connect

Cosa serve

  • API keyA key with the Viewer role: it reads everything and can change nothing.

Porta predefinita: 80

Regole di avviso incluse 9

  • AllarmeUnraid array stoppedThe Unraid array is not started: shares, containers and VMs that live on it are unavailable.
  • AllarmeUnraid disk disabled or missingAn Unraid disk is disabled, missing or invalid: the array runs degraded, and one more failure loses data.
  • AvvisoUnraid disk read errorsAn Unraid disk has reported read errors since the array started: it may be disabled at the next one.
  • AvvisoUnraid disk too hotAn Unraid array or parity disk has stayed above 55 °C for fifteen minutes.
  • AvvisoUnraid parity check found errorsThe last Unraid parity check failed or found sync errors: parity no longer matches the data.
  • AvvisoUnraid parity check overdueThe last Unraid parity check is more than 40 days old: a monthly check was missed.
Mostra altre 3
  • AvvisoUnraid cache nearly fullAn Unraid cache pool is more than 90 % full: writes fall back to the slow array, or fail.
  • AvvisoUnraid container stoppedA Docker container set to start with the array is not running.
  • AllarmeDevice unreachableNo measurement received for more than three minutes. bottomk by (target) (1, time() - tlast_over_time(dumbmonit_up[7d]))
Passaggi di configurazione: Create a read-only API key for DumbMonit

  1. On Unraid 7.2 or later the API is built in. On Unraid 6.12 to 7.1, install the Unraid Connect plugin from the Apps tab first: it brings the same API, and no Unraid Connect sign-in is needed for local use.

  2. Create an API key with the Viewer role, which reads everything and can change nothing: under Settings > Management Access > API Keys, or from the Unraid terminal.

    unraid-api apikey --create --name dumbmonit --roles VIEWER --description "DumbMonit monitoring" --json

  3. Copy the key. In DumbMonit, enter the address of the Unraid server, for example "tower.lan", and paste the key as API key. If the web interface is served over HTTPS, choose https as protocol.

Attenzione. Unraid reports no temperature for a disk that is spun down, and DumbMonit never wakes one: a sleeping disk simply has no temperature until it spins up.

Proxmox Backup Server

pbs

Backup freshness per machine, failed tasks, sync and verify jobs, datastore space.

Esempi

  • Proxmox Backup Server

Cosa serve

  • API token (recommended)No expiry and no session opened: the right choice for monitoring.
  • Username / passwordOpens a two-hour session, renewed automatically. Use it only if tokens are not an option.

Porta predefinita: 8007

Regole di avviso incluse 21

  • AvvisoPBS datastore almost fullPBS datastore more than 90% full.
  • AvvisoPBS datastore filling upAt the current rate, PBS estimates the datastore full within seven days.
  • AvvisoPBS datastore not mountedA removable datastore is not mounted: nothing can be written to it.
  • AvvisoPBS backup too oldNo new snapshot for this backup group (one per machine) for more than two days. Edit the threshold for machines backed up weekly; the notification names the group and datastore.
  • AllarmePBS backup verification failedVerification of the latest snapshot for this machine failed.
  • AvvisoPBS task failedAt least one PBS task failed in the review window.
Mostra altre 15
  • AvvisoPBS garbage collection too oldNo successful garbage collection on this datastore for more than eight days.
  • AvvisoPBS garbage collection failedThe last garbage collection on a datastore failed.
  • AllarmePBS corrupt chunks foundThe garbage collection found unreadable chunks on a datastore: some backups can no longer be restored.
  • AvvisoPBS prune job failedThe last run of a PBS prune job failed: nothing is pruned and the datastore keeps filling up. The notification names the job and datastore.
  • AvvisoPBS verification job failedThe last run of a PBS verification job failed.
  • AllarmePBS sync job failedThe last run of a PBS sync job failed.
  • AllarmePBS tape backup failedThe last tape backup run failed: the offline copy is not being made.
  • AvvisoPBS job never ranA job is enabled and scheduled but has never run.
  • AllarmePBS service downA service Proxmox Backup Server needs is not running; no backup can be taken in while it is down.
  • AllarmePBS disk SMART failureA disk of the backup server reports SMART health FAILED. The notification reads /dev/sdb.
  • AvvisoPBS SSD worn outAn SSD of the backup server has used more than 90 % of its rated endurance.
  • AllarmePBS ZFS pool degradedA ZFS pool of the backup server is not ONLINE.
  • AvvisoPBS certificate expiringThe certificate served by the backup server expires in less than three weeks. Needs the certificates option.
  • InfoPBS restart pending after upgradeThe package was upgraded but the running daemon is still the old one.
  • InfoPBS updates pendingMore than twenty package updates are pending on the backup server.
Passaggi di configurazione: Create a read-only user and token in Proxmox Backup Server

  1. Open a shell on the backup server (in the web UI: Administration → Shell; or SSH) and create a user reserved for monitoring. It needs no password: the token is what logs in.

    proxmox-backup-manager user create dumbmonit@pbs --comment "DumbMonit monitoring"

  2. Create the user's API token. The command prints the token id and its secret: copy both now, PBS never shows the secret again.

    proxmox-backup-manager user generate-token dumbmonit@pbs monitor

  3. Give the read-only minimum, per path — to the token and to the user that owns it. A token's effective privileges are the intersection of its own ACL and its user's: granted to the token alone, they amount to nothing at all, and PBS reports that nowhere. Every line is therefore written twice. DatastoreAudit on /datastore (Datastore.Audit) reads the datastores, snapshots, verify and prune jobs and GC; Audit on /system (Sys.Audit) reads the node status, the task list and task logs, the services, the traffic-control rules, the disks and ZFS pools.

    proxmox-backup-manager acl update /datastore DatastoreAudit --auth-id 'dumbmonit@pbs'
proxmox-backup-manager acl update /datastore DatastoreAudit --auth-id 'dumbmonit@pbs!monitor'
proxmox-backup-manager acl update /system Audit --auth-id 'dumbmonit@pbs'
proxmox-backup-manager acl update /system Audit --auth-id 'dumbmonit@pbs!monitor'

  4. Optional, and twice as well. RemoteAudit on /remote (Remote.Audit) shows the sync jobs that pull from a remote: the built-in Audit role covers Sys.Audit and Datastore.Audit only, and without Remote.Audit such a job is not refused, it is simply absent from the job list. TapeAudit on /tape (Tape.Audit) reads the tape tier. Audit on / (Sys.Audit at the top level) lists pending package updates, and also covers /datastore and /system if you prefer fewer lines. Without them those items are silently skipped, nothing else changes. Nothing here can write: the collector only performs GETs.

    proxmox-backup-manager acl update /remote RemoteAudit --auth-id 'dumbmonit@pbs'
proxmox-backup-manager acl update /remote RemoteAudit --auth-id 'dumbmonit@pbs!monitor'
proxmox-backup-manager acl update /tape TapeAudit --auth-id 'dumbmonit@pbs'
proxmox-backup-manager acl update /tape TapeAudit --auth-id 'dumbmonit@pbs!monitor'
proxmox-backup-manager acl update / Audit --auth-id 'dumbmonit@pbs'
proxmox-backup-manager acl update / Audit --auth-id 'dumbmonit@pbs!monitor'

  5. Copy the token id into DumbMonit's Token ID field and the secret into its Secret field.

    dumbmonit@pbs!monitor

  6. Before leaving the shell, check what the token can actually read. The command prints its effective privileges, path by path; an empty result means the user is missing the ACL the token has — the case where the device looks perfectly alive and reports nothing.

    proxmox-backup-manager user permissions 'dumbmonit@pbs!monitor'

  7. Prefer the web UI? Configuration → Access Control: Users → Add, then API Tokens → Add, then Permissions → Add. Add each permission twice, once as User Permission for dumbmonit@pbs and once as API Token Permission for dumbmonit@pbs!monitor: with path /datastore and role DatastoreAudit, then again with path /system and role Audit. A token permission on its own grants nothing.

  8. In DumbMonit, enter the server address, for example "pbs.lan" or "pbs.lan:8007".

Attenzione. Do not reuse the account you log in with: a leaked token would then manage every backup. The Audit role can only read. PBS also uses a self-signed certificate by default: if the connection is refused for that reason, tick "Accept an unverifiable certificate" in the options.

Veeam Backup & Replication

veeam

A Veeam backup server through its REST API: jobs whose last run failed, failed sessions of the last 24 hours, repositories filling up, license expiry.

Esempi

  • Veeam Backup & Replication 12
  • Veeam Backup & Replication 13
  • Veeam Community Edition

Cosa serve

  • User name and passwordThe account given the Veeam Backup Viewer role, in the form HOST\user or DOMAIN\user.

Porta predefinita: 9419

Regole di avviso incluse 6

  • AvvisoClient device staleA device has not connected or not backed up within the staleness window configured for this target.
  • AllarmeVeeam job failedThe last run of an enabled Veeam job failed: what it protects has no new restore point.
  • AvvisoVeeam job ended with a warningThe last run of an enabled Veeam job ended with a warning: some objects may not be protected.
  • AvvisoVeeam repository nearly fullA Veeam backup repository is more than 90 % full: the next jobs will fail for lack of space.
  • AvvisoVeeam license expiringThe Veeam license expires in less than 30 days: jobs stop at the end of the grace period.
  • AllarmeDevice unreachableNo measurement received for more than three minutes. bottomk by (target) (1, time() - tlast_over_time(dumbmonit_up[7d]))
Passaggi di configurazione: Give DumbMonit a Veeam Backup Viewer account

  1. On the backup server, create a local Windows account for DumbMonit with a long random password and no other right on the machine (a domain account works too).

    net user dumbmonit * /add

  2. In the Veeam console, open the main menu > Users and Roles > Security, click Add, enter the account (for example VBR01\dumbmonit) and give it the Veeam Backup Viewer role only.

  3. In DumbMonit, enter the address of the backup server, for example "vbr.lan", and the account as HOST\dumbmonit or DOMAIN\dumbmonit with its password. The REST API listens on port 9419 with a self-signed certificate: tick Accept an unverifiable certificate unless you installed your own.

Attenzione. Veeam keeps some REST API routes for the Backup Administrator role, the license among them on current versions. With the Viewer role DumbMonit reads the jobs, sessions, repositories and restore points, and shows the license as not readable: it never asks for more.
