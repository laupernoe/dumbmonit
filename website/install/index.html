Install DumbMonit

One container, three steps. Add the agent to your servers afterwards.

  1. Download the Compose file

    Make a folder and fetch the file. It already drops every capability and mounts the file system read-only.

    $ mkdir dumbmonit && cd dumbmonit
$ curl -fsSLO https://raw.githubusercontent.com/laupernoe/dumbmonit/main/docker-compose.yml

  2. Start it

    Docker pulls the image and starts DumbMonit together with its time-series database.

    $ docker compose up -d

  3. Create the first account

    Open the page and create the administrator. Then add a monitor: the form says what to prepare on it.

    Then open http://localhost:8080 and create the first account. Image for amd64 (arm64 later): ghcr.io/laupernoe/dumbmonit.

What you need

  • Docker Engine with the Compose plugin.
  • An amd64 machine; arm64 images are paused for now.
  • Port 8080 free, or another port of your choice.
  • Network access to the devices you monitor. They do not need to reach the server, except agents.

Then add the agent to your servers

A small binary that pushes CPU, memory, disks, network, services and uptime to the server, plus temperatures, fans, SMART and ZFS pools where the machine exposes them. It calls the server, never the other way round: no port to open on the machine.

# the UI fills in the token for you
curl -sSL http://server:8080/install.sh | sh -s -- \
  --token=dmon_xxx --url=http://server:8080

A PowerShell script is served at /install.ps1 for Windows. The agent is also an image, ghcr.io/laupernoe/dumbmonit-agent.

Agent documentation

  • LinuxSupportedx86_64 and aarch64, systemd or OpenRC. Docker containers and OS health (updates, pending reboot, failed units).
  • WindowsSupportedx86_64, installed as a Windows service. SMART through smartctl.
  • macOSPreviewlaunchd, Apple silicon and Intel; binaries attached to each release. Not yet run on real hardware.
  • FreeBSDPreviewrc.d, x86_64, ZFS pools. Not yet run on real hardware.

DumbMonit, Apache 2.0. The mascot is a pigeon.
